Задача: реализовать механизм калибровки масштаба изображения по измерительному отрезку.

Контекст:
- Приложение работает с изображениями проекта и хранит данные каждого изображения в JSON проекта.
- Сейчас измерения контура и цветовые свойства считаются в пикселях.
- Нужно дать пользователю возможность указать на изображении калибровочный отрезок известной длины в миллиметрах.
- По этому отрезку приложение должно вычислять соответствие между пикселями и миллиметрами для конкретного изображения.
- Калибровка относится к отдельному изображению, а не ко всему проекту.

Область изменений:
- Канвас изображения и режимы взаимодействия с ним.
- Меню/панель инструментов GUI.
- Модель данных записи изображения и JSON проекта.
- Панель "Свойства изображения", группа "Информация о контуре".
- Сохранение и загрузка проекта.
- Тесты модели, UI-состояний, JSON и расчёта масштаба.

Требования к пользовательскому сценарию:
- Добавить инструмент "Калибровка" или "Калибровать масштаб" на панель инструментов и/или в меню.
- При активации инструмента пользователь должен указать на изображении две точки: начало и конец калибровочного отрезка.
- После выбора двух точек должен открыться диалог ввода реальной длины этого отрезка в миллиметрах.
- Пользователь вводит положительное числовое значение в миллиметрах.
- После подтверждения приложение сохраняет:
  - координаты начала отрезка в пикселях;
  - координаты конца отрезка в пикселях;
  - реальную длину отрезка в миллиметрах;
  - вычисляемый масштаб, если его удобно хранить или пересчитывать.
- Если пользователь отменяет диалог, калибровка не должна изменяться.
- Если введено некорректное значение, нужно показать понятное предупреждение и не сохранять некорректную калибровку.

Требования к редактированию:
- Существующую калибровку выбранного изображения нужно отображать на канвасе как отдельный отрезок с двумя редактируемыми узлами.
- Пользователь должен иметь возможность изменить калибровку:
  - заново выбрать инструмент и задать новый отрезок;
  - либо переместить узлы существующего калибровочного отрезка, если такой способ хорошо вписывается в текущую логику редактирования узлов.
- При перемещении узлов калибровочного отрезка длина в пикселях и масштаб должны пересчитываться автоматически, а длина в миллиметрах должна оставаться прежней.
- Добавить возможность сбросить калибровку для текущего изображения.
- Сброс калибровки должен удалять отрезок и связанные значения только у выбранного изображения.

Требования к интерфейсу:
- В панели "Свойства изображения" в группе "Информация о контуре" добавить свойство масштаба изображения.
- Название свойства можно выбрать в стиле интерфейса, например:
  - "Масштаб";
  - или "Калибровка";
  - или "Соответствие пикселей и мм".
- Значение должно быть человекочитаемым и показывать связь пикселей и миллиметров, например:
  - `120 px = 10 мм`;
  - `12.00 px/мм`;
  - `0.0833 мм/px`.
- Если калибровка отсутствует, показывать пустое состояние в стиле существующих вычисляемых свойств, например "-".
- Действия калибровки должны быть включены только когда выбрано изображение проекта.
- Инструмент калибровки не должен конфликтовать с режимом редактирования контура: пользователь должен понимать, редактирует он контур или калибровочный отрезок.
- Визуальный стиль отрезка должен отличаться от контура, например цветом, пунктиром или маркерами, но оставаться аккуратным в текущей теме.

Требования к расчётам:
- Длина калибровочного отрезка в пикселях рассчитывается как евклидово расстояние между двумя точками.
- Масштаб:
  - `pixels_per_mm = pixel_length / real_length_mm`;
  - `mm_per_pixel = real_length_mm / pixel_length`.
- Если расстояние между точками равно нулю или слишком мало для корректного расчёта, калибровку нельзя сохранять.
- Значения должны округляться для отображения, но в JSON желательно хранить исходные числовые данные с достаточной точностью.
- При изменении координат отрезка масштаб должен пересчитываться.
- В будущих измерениях площади/длины можно будет использовать масштаб, но в этой задаче не нужно пересчитывать все существующие метрики, если это не указано отдельно.

Требования к JSON и модели данных:
- Добавить необязательное поле калибровки в запись конкретного изображения.
- Поле должно отсутствовать или быть `null`, если калибровка не задана.
- Рекомендуемая структура, если она не конфликтует с текущей моделью:
  - группа `calibration`;
  - `start`: координаты первой точки в пикселях;
  - `end`: координаты второй точки в пикселях;
  - `length_mm`: реальная длина отрезка в миллиметрах.
- Вычисляемые значения `pixels_per_mm` и `mm_per_pixel` можно не хранить, если они надёжно пересчитываются из координат и `length_mm`.
- Открытие старых JSON-проектов без поля калибровки должно работать без миграции и ошибок.
- При сохранении проекта калибровка должна сохраняться и восстанавливаться при повторном открытии.
- Некорректные или неполные данные калибровки в JSON не должны ломать загрузку проекта; такую калибровку нужно игнорировать или помечать как ошибочную в стиле существующей обработки аннотаций.

Требования к поведению:
- При выборе изображения с сохранённой калибровкой отрезок должен отображаться на канвасе.
- При выборе изображения без калибровки отрезок не должен отображаться, а свойство масштаба должно показывать "-".
- При переключении между изображениями калибровочный отрезок должен соответствовать выбранному изображению.
- При закрытии проекта, удалении изображения или сбросе калибровки UI должен очищаться корректно.
- Автосохранение проекта должно срабатывать после создания, редактирования или сброса калибровки.
- Калибровка не должна менять контур листа, цветовые расчёты, гистограммы, список изображений и существующие метаданные, кроме прямой необходимости обновить состояние действий.

Рекомендации по реализации:
- Добавить в модель отдельную структуру калибровки, например `ImageCalibration` или аналогичный dataclass.
- В канвасе отделить калибровочные узлы от узлов контура, чтобы действия удаления/перемещения не путали два типа объектов.
- Если текущий канвас уже умеет редактировать узлы контура, можно переиспользовать часть логики hit-test/drag, но не смешивать данные контура и калибровки.
- Добавить отдельный сигнал канваса о смене калибровки, чтобы главное окно обновляло свойства и планировало сохранение проекта.
- Для диалога ввода длины использовать `QInputDialog.getDouble` или небольшой собственный диалог с валидацией положительного значения.
- Добавить понятные подсказки и status tip для действия калибровки.
- Сохранить текущие паттерны проекта для иконок, меню, toolbar actions, сигналов и тестов.

Критерии приемки:
- В интерфейсе есть инструмент для задания калибровочного отрезка на выбранном изображении.
- Пользователь может выбрать две точки на изображении и ввести реальную длину отрезка в миллиметрах.
- После подтверждения калибровочный отрезок отображается на канвасе.
- В группе "Информация о контуре" панели "Свойства изображения" отображается вычисленный масштаб.
- Калибровка сохраняется в JSON конкретного изображения и восстанавливается после повторного открытия проекта.
- Старые проекты без калибровки открываются без ошибок.
- Калибровку можно изменить и сбросить.
- При перемещении узлов калибровочного отрезка масштаб пересчитывается.
- При отсутствии калибровки отображается "-".
- Некорректная длина в миллиметрах или нулевой отрезок не сохраняются.
- Существующие сценарии работы с контуром, цветовые свойства, экспорт, метаданные, ID изображения и сохранение проекта продолжают работать.
- Существующие тесты проходят; добавлены или обновлены тесты на JSON round-trip калибровки, расчёт масштаба, пустое состояние, создание/сброс калибровки и восстановление отрезка при выборе изображения.
