Задача: добавить в панели свойств вычисляемые группы для цветовых пространств HSV, YUV и LMS.

Контекст:
- В приложении есть панели "Свойства изображения" и "Свойства проекта".
- В обеих панелях уже используются группы вычисляемых цветовых свойств RGB и Lab.
- Нужно по аналогии добавить группы для цветовых пространств HSV, YUV и LMS.
- Можно ориентироваться на промпты `prompts/prompts05/0002_improved.txt` и `prompts/prompts05/0003_improved.txt`.
- Значения новых цветовых пространств должны быть вычисляемыми и не должны сохраняться в JSON проекта.

Область изменений:
- Панель "Свойства изображения".
- Панель "Свойства проекта".
- Логика вычисления цветовых статистик по пикселям внутри контура.
- Общие helper'ы преобразования RGB-пикселей в HSV, YUV и LMS.
- Экспорт свойств изображения в Excel, если он строится из общего списка групп панели "Свойства изображения".
- Тесты, проверяющие порядок групп, корректность расчётов, пустые состояния и отсутствие новых JSON-полей.

Требования к интерфейсу:
- В панели "Свойства изображения" добавить группы сразу после уже существующих цветовых групп RGB и Lab:
  - "Цветовое пространство HSV" со свойствами "H", "S", "V".
  - "Цветовое пространство YUV" со свойствами "Y", "U", "V".
  - "Цветовое пространство LMS" со свойствами "L", "M", "S".
- В панели "Свойства проекта" добавить группы сразу после уже существующих цветовых групп RGB и Lab:
  - "Цветовое пространство HSV" со свойствами "Средний H", "Средний S", "Средний V".
  - "Цветовое пространство YUV" со свойствами "Средний Y", "Средний U", "Средний V".
  - "Цветовое пространство LMS" со свойствами "Средний L", "Средний M", "Средний S".
- Все новые свойства должны быть read-only.
- Группы должны использовать текущий property browser, поддерживать сворачивание/разворачивание и общий визуальный стиль приложения.
- Если изображение/проект не выбран, контур отсутствует или данных для расчёта нет, показывать пустое состояние в стиле существующих вычисляемых свойств, например "-".

Порядок групп:
- В панели "Свойства изображения" цветовые группы должны идти компактным блоком после группы "Информация о контуре":
  - "Цветовое пространство RGB".
  - "Цветовое пространство Lab".
  - "Цветовое пространство HSV".
  - "Цветовое пространство YUV".
  - "Цветовое пространство LMS".
  - затем существующие нецветовые группы, например "Локация" и "Дополнительно".
- В панели "Свойства проекта" цветовые группы должны идти после "Общие свойства":
  - "Цветовое пространство RGB".
  - "Цветовое пространство Lab".
  - "Цветовое пространство HSV".
  - "Цветовое пространство YUV".
  - "Цветовое пространство LMS".

Требования к расчётам для "Свойства изображения":
- Рассчитывать значения по пикселям внутри текущего контура выбранного изображения.
- Использовать тот же набор RGB-пикселей, который применяется для расчёта RGB, Lab и количества пикселов контура.
- При изменении, создании или удалении контура значения должны обновляться автоматически.
- При отсутствии выбранного изображения, контура, файла или корректных пикселей показывать "-".

Требования к расчётам для "Свойства проекта":
- Рассчитывать средние значения по пикселям внутри контуров всех изображений проекта.
- Использовать те же правила отбора изображений, что и для проектных RGB/Lab:
  - учитывать только существующие и корректно загружаемые файлы;
  - учитывать только изображения с корректной аннотацией контура;
  - пропускать изображения без контура, с ошибкой аннотации, отсутствующим файлом, несовпадающим размером аннотации или пустой областью внутри контура.
- Использовать тот же набор пикселей, который участвует в расчёте проектных RGB/Lab, чтобы все цветовые пространства описывали одну и ту же совокупность данных.
- Значения должны обновляться при открытии проекта, добавлении/удалении/синхронизации изображений, изменении контура и изменении состава проекта.

Требования к шкалам и преобразованиям:
- HSV:
  - преобразовывать RGB -> HSV через существующий стек проекта, предпочтительно `OpenCV`.
  - Если исходные пиксели хранятся как RGB, использовать корректный код преобразования, например `cv2.COLOR_RGB2HSV`.
  - Для отображения H использовать человекочитаемую шкалу 0..360, согласованную с существующей HSV-гистограммой.
  - S и V отображать в шкале 0..255.
- YUV:
  - преобразовывать RGB -> YUV через `OpenCV`, например `cv2.COLOR_RGB2YUV`.
  - Отображать Y, U и V в шкале 0..255, как в текущей YUV-гистограмме.
- LMS:
  - Использовать тот же подход, который уже применяется в LMS-гистограмме приложения: linear sRGB -> XYZ D65 -> LMS через Bradford matrix.
  - Для отображения значений использовать шкалу, согласованную с LMS-гистограммой. Если значения нормализуются в 0..255, применить тот же способ нормализации и описать это в helper'е/тестах.
- Для всех пространств формат отображения должен быть компактным: числовые строки без лишних пояснений.
- Округление должно быть единообразным с текущими RGB/Lab-значениями, например `np.rint(...).astype(int)`.

Требования к данным и JSON:
- Не добавлять HSV, YUV и LMS-значения в JSON проекта.
- Не менять формат проекта, записи изображений, аннотации и существующие группы `file`, `contour`, `location`, `details`.
- Открытие старых проектов должно работать без миграции.
- Сохранение проекта после просмотра новых свойств не должно создавать новых полей только из-за вычислений.

Требования к экспорту:
- Если экспорт свойств изображения в Excel строится из общего списка групп панели "Свойства изображения", добавить новые группы и свойства в этот список.
- В диалоге выбора свойств для экспорта новые группы должны отображаться в том же порядке, что и в панели.
- В Excel должны попадать отображаемые значения HSV, YUV и LMS.
- При отсутствии данных экспорт должен использовать то же пустое значение, которое отображается в интерфейсе.
- Не добавлять новые столбцы в экспорт списка изображений проекта, если для этого нет отдельного требования.

Рекомендации по реализации:
- Вынести преобразования в небольшие helper'ы рядом с текущими helper'ами RGB/Lab, например:
  - RGB-пиксели -> средние HSV.
  - RGB-пиксели -> средние YUV.
  - RGB-пиксели -> средние LMS.
- Для расчётов проекта желательно проходить по пикселям контуров один раз и накапливать суммы для всех нужных цветовых пространств.
- Для расчётов изображения использовать уже полученный массив пикселей текущего контура, не строить маску повторно.
- Если в `histograms.py` уже есть функции преобразования для HSV/YUV/LMS, переиспользовать их напрямую или вынести общую часть без дублирования формул.
- При программном обновлении значений не запускать обработчики редактируемых полей и не раскрывать группы самопроизвольно.
- Не менять логику контуров, JSON, канваса, меню, тулбара, гистограмм и сохранения, кроме точечных изменений для переиспользования helper'ов.

Критерии приемки:
- В панели "Свойства изображения" появились группы "Цветовое пространство HSV", "Цветовое пространство YUV" и "Цветовое пространство LMS" после RGB/Lab.
- В панели "Свойства проекта" появились группы "Цветовое пространство HSV", "Цветовое пространство YUV" и "Цветовое пространство LMS" после RGB/Lab.
- Для изображения с корректным контуром все новые значения вычисляются по пикселям внутри текущего контура.
- Для проекта значения вычисляются по пикселям внутри всех доступных корректных контуров.
- При изменении контура или состава проекта новые значения обновляются без перезапуска приложения.
- При отсутствии данных отображается "-".
- Новые значения не сохраняются в JSON проекта.
- Экспорт свойств изображения в Excel включает новые группы и свойства, если пользователь выбирает их для экспорта.
- Существующие RGB и Lab свойства, метаданные, ID, переименование файла, выбор даты/времени, экспорт и сохранение проекта продолжают работать как раньше.
- Существующие тесты проходят; добавлены или обновлены тесты на порядок новых групп, корректные значения HSV/YUV/LMS, пустые состояния, экспорт свойств изображения и отсутствие новых JSON-полей.
