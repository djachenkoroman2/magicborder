Задача: заменить текущую самописную разметку панелей свойств на Qt Property Browser.

Контекст:
- В интерфейсе уже есть панели "Свойства проекта" и "Свойства изображения".
- Сейчас свойства в этих панелях отображаются через собственный helper на базе `QVBoxLayout`, `QFormLayout`, `QToolButton`, `QLabel`, `QLineEdit` и `QTextEdit`.
- Нужно отказаться от текущего подхода к отображению свойств в этих двух панелях и использовать Qt Property Browser или PyQt5-совместимую реализацию Qt Property Browser.
- При этом существующая бизнес-логика проекта, структура JSON, вычисляемые значения и обработчики редактирования должны сохраниться.

Область изменений:
- Панель "Свойства проекта".
- Панель "Свойства изображения".
- Общий код создания, группировки, обновления и редактирования свойств, если он используется обеими панелями.
- При необходимости добавить небольшой внутренний адаптер/слой привязки между моделью данных приложения и виджетами Qt Property Browser.

Требования к интерфейсу:
- Свойства должны отображаться в древовидном property browser с группами, соответствующими текущим группам панелей.
- Группы должны быть сворачиваемыми и разворачиваемыми средствами property browser.
- По умолчанию группы должны быть свёрнуты, если это поддерживается выбранной реализацией без нестабильных хаков. Если реализация не позволяет надёжно задать начальное состояние, явно описать и покрыть выбранное поведение.
- Внешний вид должен оставаться аккуратным и соответствовать текущей светлой теме приложения.
- Между свёрнутыми группами не должно появляться больших пустых промежутков.
- Пустые состояния "Проект не открыт." и "Изображение не выбрано." должны работать как раньше.
- Заголовки панелей и кнопка экспорта свойств изображения в Excel должны сохраниться.

Требования к свойствам проекта:
- В группе "Общие свойства" оставить:
  - "Общая информация" - редактируемое текстовое свойство, сохраняется в JSON проекта.
  - "Количество изображений" - вычисляемое read-only свойство.
- В группе "Цветовое пространство RGB" оставить вычисляемые read-only свойства:
  - "Средний R".
  - "Средний G".
  - "Средний B".
- Редактирование "Общей информации" должно сохранять текущее поведение: значение обновляется в модели проекта и записывается при сохранении проекта.

Требования к свойствам изображения:
- Сохранить все текущие группы и свойства панели "Свойства изображения":
  - "Общая информация о файле": ID, файл, путь, размер, статус, дата добавления, дата съёмки.
  - "Информация о контуре": аннотация, количество узлов контура, количество пикселов контура.
  - "Цветовое пространство RGB": красный, зелёный, синий, средний цвет.
  - "Локация": освещённость, влажность, скорость ветра, направление ветра, широта, долгота.
  - "Дополнительно": диагноз, дополнительные сведения.
- Редактируемые свойства должны оставаться редактируемыми.
- Вычисляемые свойства и свойства, которые пользователь не должен менять напрямую, должны быть read-only.
- Для ID изображения сохранить проверку уникальности, возможность ручного редактирования и генерацию нового ID текущей кнопкой.
- Для имени файла сохранить текущую логику переименования и кнопку переименования файла по ID.
- Для дат сохранить текущий сценарий выбора даты/времени через существующий диалог или эквивалентный редактор, не ухудшающий UX.
- Для длинных текстовых полей, таких как "Общая информация" и "Дополнительные сведения", обеспечить удобное редактирование. Если выбранный property browser не поддерживает многострочный редактор напрямую, использовать безопасный делегат, отдельный диалог редактирования или другой PyQt5-совместимый способ.
- Для "Средний цвет" сохранить визуальный цветовой индикатор или заменить его на эквивалентное отображение внутри property browser, если оно выглядит аккуратно и не ломает экспорт.

Технические требования:
- Перед внедрением проверить, доступна ли в текущем окружении PyQt5-совместимая реализация Qt Property Browser.
- Если готовой зависимости в проекте нет, выбрать один из подходов:
  - добавить поддерживаемую PyQt5-совместимую зависимость, если она стабильно устанавливается через `uv` и не конфликтует с текущими версиями PyQt5;
  - либо добавить локальную минимальную реализацию/порт Qt Property Browser в код проекта, если это надёжнее для приложения.
- Не добавлять тяжёлые или неподдерживаемые зависимости без необходимости.
- Не смешивать старую `QFormLayout`-разметку свойств с новым property browser, кроме небольших вспомогательных виджетов, которые нужны как редакторы значений.
- Свести дублирование к минимуму: описание групп и свойств должно быть достаточно декларативным, чтобы будущие свойства можно было добавлять без переписывания всего UI.
- Для обновления значений использовать текущие места, где уже обновляются свойства проекта и изображения, либо аккуратно вынести синхронизацию в общий helper.
- Изменение UI не должно менять формат JSON проекта, экспорт Excel, вычисление RGB, работу контуров, список изображений, канвас, меню, тулбар и гистограммы.

Требования к поведению:
- При открытии проекта property browser панели проекта показывает актуальные значения.
- При выборе изображения property browser панели изображения показывает актуальные значения выбранного изображения.
- При добавлении, удалении, синхронизации изображений и изменении контура вычисляемые свойства обновляются как раньше.
- При закрытии проекта или отсутствии выбранного изображения панели переходят в корректное пустое состояние.
- Редактирование значений через property browser обновляет модель только после осмысленного изменения значения и не запускает лишние сохранения.
- Сигналы редакторов не должны создавать циклические обновления, потерю фокуса, двойные записи или случайное раскрытие групп.

Рекомендации по реализации:
- Начать с небольшого адаптера свойств: ключ свойства, заголовок, группа, тип редактора, read-only флаг, getter, setter или callback.
- Для read-only значений использовать отключённые или read-only properties, а не обычные labels вне browser.
- Для строковых значений использовать строковый редактор property browser.
- Для числовых вычисляемых значений можно хранить отображаемую строку, если приложение уже показывает человекочитаемые значения.
- Для цвета рассмотреть property типа color, если выбранная реализация его поддерживает, или компактный custom editor.
- Убедиться, что при программном обновлении значений используются блокировщики сигналов или другой механизм, предотвращающий вызов пользовательских обработчиков.
- Сохранить текущие имена пользовательских групп и свойств на русском языке.

Критерии приемки:
- Панели "Свойства проекта" и "Свойства изображения" используют Qt Property Browser вместо текущей самописной формы на `QFormLayout`.
- Все существующие группы и свойства присутствуют и отображаются с прежними русскими названиями.
- Редактируемые свойства можно менять, и изменения корректно попадают в модель проекта.
- Read-only и вычисляемые свойства нельзя редактировать вручную.
- Сохранение и повторное открытие проекта восстанавливает редактируемые значения.
- Вычисляемые свойства проекта и изображения обновляются в тех же сценариях, что и до изменения интерфейса.
- Сворачивание и разворачивание групп работает средствами property browser, без больших пустых промежутков.
- Экспорт списка изображений и экспорт свойств изображения в Excel продолжают работать.
- Существующие сценарии с ID изображения, переименованием файла по ID, выбором даты/времени, заметками и диагностикой продолжают работать.
- Существующие тесты проходят; при необходимости добавлены или обновлены тесты на создание property browser, обновление read-only значений и запись редактируемых свойств.
