Задача: реализовать в MagicBorder классификатор оценок OIV для измерений углов и отрезков на основании справочника `doc/oiv_ampelometric_traits_601_615_617.md`.

Исходная формулировка:
"1. На основании doc/oiv_ampelometric_traits_601_615_617.md необходимо построить классификатор, который на основе OIV признака и соответствующего показателя дает оценку либо по длине отрезка либо по значению угла.
2. Данные для продукционной системы, которая делает выбор на основании шкал doc/oiv_ampelometric_traits_601_615_617.md предлагаю хранить в формате JSON в корневом каталоге проекта.
3. Попытаться сделать формат универсальным, что бы его можно было использовать как для углов, так и для отрезков и других объектов не являющимися отрезками илли углами.
4. В элементах подгрупп измерения в подгруппах углы и отрезки предусмотреть для каждого итема элемент с названием "Оценка" где можно выбрать номер oiv и его краткое наименование и получить значение в вычисляемом поле его оценки по соответствующей шкале.
5. Выбор oiv для итема это элемент проекта, а значение определяется по факту по узлам (отрезков или углов)
6. Один номер oiv один угол или один отрезок."

Контекст проекта:
- MagicBorder - локальное настольное приложение на Python и `PyQt5`.
- Формат проекта описан в `src/magicborder/models.py`; записи изображений содержат группу `measurements`.
- Измерения уже разделены на:
  - `measurements.angles` / `ProjectAngleMeasurement`;
  - `measurements.segments` / `ProjectSegmentMeasurement`.
- Панель свойств выбранного изображения строится в `src/magicborder/main_window.py`.
- В панели уже есть группа `Измерения` с подгруппами `Углы` и `Отрезки`.
- Для углов уже вычисляется значение в градусах.
- Для отрезков уже вычисляется длина в пикселях и, при наличии калибровки, в миллиметрах.

Главное требование:
- Добавить возможность назначить каждому измерению ровно один OIV-признак.
- По выбранному OIV-признаку автоматически вычислять оценку по шкале из `doc/oiv_ampelometric_traits_601_615_617.md`.
- Выбор OIV должен сохраняться в JSON проекта как свойство конкретного угла или отрезка.
- Вычисленная оценка не должна быть ручным полем: она каждый раз считается из текущей геометрии узлов, калибровки и справочника шкал.
- Шкалы не хардкодить в UI-коде; вынести данные продукционной системы в отдельный JSON-файл в корне репозитория.

Файл данных OIV:
- Создать в корне репозитория JSON-файл, рекомендуемое имя:
  - `oiv_ampelometric_scales.json`.
- Заполнить его только данными из `doc/oiv_ampelometric_traits_601_615_617.md`.
- JSON должен быть пригоден не только для углов и отрезков, но и для будущих типов измерений.
- Минимальная рекомендуемая структура:

```json
{
  "version": 1,
  "source": "doc/oiv_ampelometric_traits_601_615_617.md",
  "traits": [
    {
      "code": "OIV 601",
      "short_name": "Длина жилки N1",
      "official_name": "Mature leaf: length of vein N1",
      "measurement_kind": "length",
      "tool_kinds": ["segment"],
      "unit": "mm",
      "scale": [
        {
          "score": 1,
          "label": "очень короткая",
          "min": null,
          "max": 90,
          "include_min": true,
          "include_max": false,
          "comment": "..."
        }
      ]
    }
  ]
}
```

Требования к JSON-формату:
- `code` писать единообразно: `OIV 601`, `OIV 602`, ... `OIV 615`, `OIV 617`.
- `measurement_kind` использовать как тип оцениваемой величины, а не как тип UI-виджета:
  - `length` для линейных размеров в миллиметрах;
  - `angle` для углов в градусах;
  - формат должен допускать будущие значения вроде `count`, `ratio`, `area`, `enum`.
- `tool_kinds` использовать для фильтрации доступных OIV в интерфейсе:
  - для текущих отрезков - `segment`;
  - для текущих углов - `angle`.
- `unit` указывать явно:
  - `mm` для длин;
  - `deg` для углов.
- `scale` должна содержать детерминированные диапазоны `min`/`max`, чтобы классификатор не гадал.
- Диапазоны не должны пересекаться и не должны оставлять дыр для обычных положительных значений.
- Для граничных значений использовать единое правило: нижняя граница включительно, верхняя граница исключительно; последняя открытая граница включает все большие значения.
- Если в исходном справочнике шкала задана опорными значениями, а не явными интервалами, сформировать интервалы по серединам между соседними опорными значениями и зафиксировать это в JSON через поле вроде `boundary_method`.
- Не добавлять в JSON `OIV 616` как доступный для выбора признак.

Доступные признаки:
- Для отрезков должны быть доступны:
  - `OIV 601`;
  - `OIV 602`;
  - `OIV 603`;
  - `OIV 604`;
  - `OIV 605`;
  - `OIV 606`;
  - `OIV 611`;
  - `OIV 612`;
  - `OIV 613`;
  - `OIV 614`;
  - `OIV 615`;
  - `OIV 617`.
- Для углов должны быть доступны:
  - `OIV 607`;
  - `OIV 608`;
  - `OIV 609`;
  - `OIV 610`.
- В выпадающем списке показывать код и краткое название, например:
  - `OIV 607 - угол между N1 и N2`;
  - `OIV 601 - длина жилки N1`.
- Первым пунктом списка должен быть вариант `Не выбрано`.

Модель данных проекта:
- Добавить в `ProjectAngleMeasurement` и `ProjectSegmentMeasurement` поле для выбора OIV.
- Рекомендуемый формат в JSON проекта:

```json
{
  "id": "segment-1",
  "name": "N1",
  "start": { "x": 10, "y": 20 },
  "end": { "x": 80, "y": 20 },
  "assessment": {
    "system": "OIV",
    "code": "OIV 601"
  }
}
```

- Можно выбрать другое имя поля, если оно лучше совпадает с локальным стилем проекта, но структура должна оставлять место для будущих систем оценки.
- Для старых проектов без этого поля загрузка должна работать без ошибок.
- Если в старом или ручном JSON указан неизвестный OIV-код, не ломать загрузку проекта; в UI показать отсутствие вычисленной оценки или понятное предупреждение.
- Сохранять только выбранный OIV-код. Вычисленный score, текст оценки и фактическое значение не сохранять как источник истины.

Логика классификатора:
- Создать отдельный модуль для загрузки шкал и вычисления оценок, например `src/magicborder/oiv.py`.
- Модуль должен:
  - загрузить `oiv_ampelometric_scales.json`;
  - валидировать базовую структуру;
  - отдавать список признаков по `tool_kind`;
  - находить признак по коду;
  - классифицировать числовое значение по шкале;
  - возвращать структурированный результат: фактическое значение, единица измерения, код OIV, score, словесное значение шкалы, комментарий или статус ошибки.
- Для углов использовать значение в градусах.
- Для отрезков использовать значение в миллиметрах.
- Если у изображения нет калибровки, для отрезков с OIV показывать статус `Нужна калибровка`, а не классифицировать длину в пикселях.
- Если геометрия некорректна, например нулевой угол или нулевой отрезок, показывать `-` или короткий диагностический статус.
- Если OIV выбран, но его `tool_kinds` не подходит текущему типу измерения, не падать; показать `Несовместимый признак` и сохранить возможность поменять выбор.

Интерфейс в панели свойств:
- В `Измерения -> Углы -> <конкретный угол>` добавить элемент с названием `Оценка`.
- В `Измерения -> Отрезки -> <конкретный отрезок>` добавить элемент с названием `Оценка`.
- Элемент `Оценка` должен позволять выбрать OIV-код и краткое название из выпадающего списка.
- Рядом или отдельной read-only строкой показать вычисленный результат:
  - фактическое значение, например `52.3°` или `136.2 мм`;
  - score OIV, например `5`;
  - словесную оценку, например `средняя`;
  - краткий комментарий, если он помещается без перегрузки UI.
- Если удобнее для текущего `PropertyBrowser`, допустимо сделать две строки:
  - `Оценка` - выпадающий список выбора OIV;
  - `Результат оценки` - вычисляемое read-only значение.
- При изменении выбора OIV сразу сохранять выбор в модель проекта и планировать сохранение проекта.
- При перемещении узлов измерения, изменении калибровки или смене текущего изображения пересчитывать отображаемый результат.
- Не требовать от пользователя вручную пересоздавать измерение, чтобы оценка обновилась.

Экспорт свойств изображения:
- Если выбран OIV-признак, добавить в экспорт свойств изображения информацию по измерению:
  - выбранный OIV-код;
  - краткое название;
  - фактическое значение;
  - вычисленный score;
  - словесное значение шкалы.
- Если OIV не выбран, экспорт не должен заполняться лишним шумом.
- Существующий экспорт без выбранных OIV должен продолжить работать как раньше.

Ограничения:
- Не менять смысл существующих инструментов измерения.
- Не ломать существующие проекты без OIV-оценок.
- Не добавлять новые внешние зависимости.
- Не переносить шкалы из JSON обратно в Python-код.
- Не включать `OIV 616` как доступный для выбора OIV-признак.
- Не менять исходный справочный документ `doc/oiv_ampelometric_traits_601_615_617.md`, если это не требуется для исправления явной ошибки.
- Не делать автоматическое распознавание анатомических точек листа: пользователь сам создает нужный угол или отрезок, а приложение только классифицирует числовое значение.

Рекомендуемые места изменений:
- `oiv_ampelometric_scales.json` - данные шкал и диапазонов.
- `src/magicborder/oiv.py` - загрузка шкал, проверка и классификация.
- `src/magicborder/models.py` - сохранение выбранного OIV у углов и отрезков.
- `src/magicborder/main_window.py` - UI выбора и отображение результата в `Измерения -> Углы` и `Измерения -> Отрезки`.
- `tests/test_project_models.py` - round-trip выбранного OIV в JSON проекта и загрузка старого JSON без OIV.
- Новый тестовый файл вроде `tests/test_oiv_classifier.py` - проверка классификации по шкалам.
- При необходимости обновить `README.md` разделом о выборе OIV-оценок.

Проверки перед завершением:
- В корне репозитория создан валидный JSON со шкалами OIV.
- JSON содержит все нужные коды `OIV 601`-`OIV 615` и `OIV 617`, кроме `OIV 616`.
- Для углов в UI доступны только угловые OIV.
- Для отрезков в UI доступны только линейные OIV.
- У каждого угла и отрезка можно выбрать максимум один OIV.
- Выбранный OIV сохраняется в JSON проекта и восстанавливается после открытия проекта.
- Оценка пересчитывается при изменении геометрии измерения.
- Для отрезков без калибровки показывается понятный статус, а не ошибочная оценка по пикселям.
- Старые проекты без поля оценки открываются и сохраняются без регрессий.
- Тесты проекта проходят:
  - `uv run pytest`.

Критерии готовности:
- Пользователь создает угол или отрезок, открывает свойства изображения, в группе конкретного измерения выбирает `Оценка -> OIV ...` и сразу видит оценку по шкале OIV.
- Результат основан на текущем числовом измерении, а не на ручном вводе.
- Данные шкал лежат в отдельном JSON и могут быть расширены для будущих типов объектов.
- Реализация покрыта тестами на сериализацию и классификацию.
