1. В проекте необходимо создать универсальный механизм для сборки портируемых версий приложения проекта.
2. **Главная идея:** универсальным должен быть не один бинарник для всех ОС, а единый сценарий сборки, который запускается на каждой целевой платформе и выдает одинаково устроенные артефакты.

Для MagicBorder я бы предложил такую стратегию.

**1. Базовый слой**
- `uv` остается источником воспроизводимой среды: `uv sync --frozen`.
- Python для сборок: CPython `3.12.x`, в рамках уже заданного `>=3.11,<3.14`.
- Сборка всегда из lock-файла, без “самообновления” зависимостей.
- Для Linux собирать на самой старой поддерживаемой системе/контейнере, потому что PyInstaller не бандлит `glibc`, и бинарник может не работать на более старой системе. Это прямо отмечено в документации PyInstaller.

**2. Рекомендованный первый backend: PyInstaller**
Почему:
- Хорошо подходит для PyQt-приложений, `numpy`, OpenCV и desktop GUI.
- Документация прямо говорит, что PyInstaller собирает приложение с Python и зависимостями в пакет, но не является кросс-компилятором: Windows-сборку нужно делать на Windows, Linux на Linux и т.д.
- Для вашего текущего PyQt5-приложения это самый прагматичный первый шаг.

Источник: [PyInstaller docs](https://pyinstaller.org/en/stable/) и [Linux notes](https://pyinstaller.org/en/latest/usage.html).

**3. Предлагаемая архитектура в проекте**
```text
build_tools/
  portable_build.py
  backends/
    pyinstaller.py
    cxfreeze.py
    nuitka.py
  manifests/
    magicborder.toml

dist/
  linux-x86_64/
  windows-x86_64/
  macos-x86_64/
  macos-arm64/
```

`magicborder.toml` должен описывать общее:
- имя приложения;
- версию;
- entrypoint: `magicborder.main:main`;
- GUI/console режим;
- иконки;
- включаемые данные:
  - `src/magicborder/assets`;
  - `oiv_ampelometric_scales.json`;
- исключения;
- smoke-test после сборки.

**4. Форматы артефактов**
- Windows: portable `.zip` с папкой приложения, позже MSI.
- Linux: `.tar.gz` portable-папка, позже AppImage.
- macOS: `.app`, позже `.dmg`.
- Для каждого: `magicborder-{version}-{platform}-{arch}`.

**5. CI/сборочная матрица**
Сборка должна идти отдельными job-ами:
- `windows-latest` -> Windows x86_64;
- `ubuntu-22.04` или более старый совместимый контейнер -> Linux x86_64;
- `macos-13` -> macOS x86_64;
- `macos-14`/`macos-latest` -> macOS arm64.

В каталоге doc сделай подробную документацию для сборки портируемых приложений под разные платформы
