Задача: уточнить поведение поля `Имя проекта` в панели `Свойства проекта`: имя проекта должно быть именем JSON-файла проекта без расширения, а изменение имени должно переименовывать файл проекта.

Исходная формулировка:
"1. Имя проекта это и есть имя файла только в окне свойств оно указывается без расширения
2. Любые изменения с именем проекта автоматически проходят с именем файла и соответственно все должно обновляться в окне свойств
3. Количество файлов должно идти сразу после пути"

Контекст текущей реализации:
- Панель `Свойства проекта` находится в `src/magicborder/main_window.py`.
- После предыдущей задачи в группе `Общие свойства` уже есть поля:
  - `Имя проекта`;
  - `Путь`;
  - `Общая информация`;
  - `Количество изображений`.
- Поле `Имя проекта` сейчас редактирует `ProjectDocument.name`, но не переименовывает JSON-файл проекта.
- Поле `Путь` показывает `MainWindow.project_path` и доступно только для чтения.
- Сохранение проекта выполняется через `save_project`, `_schedule_project_save()` и `_save_project_silently()`.
- Заголовок окна обновляется через `_update_window_title()`.

Цель:
- Сделать имя проекта производным от имени файла проекта:
  - если файл проекта `/path/Leaves_2026.json`, в поле `Имя проекта` показывать `Leaves_2026`;
  - `ProjectDocument.name` должен соответствовать этому имени;
  - расширение `.json` в UI не показывать.
- При редактировании поля `Имя проекта` автоматически переименовывать JSON-файл проекта в той же папке.
- После переименования сразу обновлять:
  - `self.project_path`;
  - поле `Путь`;
  - `self.project_document.name`;
  - заголовок окна;
  - сохраненный JSON проекта.
- Переставить строку количества файлов сразу после `Путь`.

Ожидаемый порядок строк в группе `Общие свойства`:
```text
--- Общие свойства
Имя проекта
Путь
Количество файлов
Общая информация
```

Если в коде сейчас используется строка `Количество изображений`, заменить ее в панели проекта на `Количество файлов`. Значение остается прежним: количество записей изображений в текущем проекте, то есть `len(self.project_document.images)`.

Правила отображения имени проекта:
- При создании проекта:
  - имя в панели должно быть равно stem имени JSON-файла проекта;
  - например `Leaves_2026.json` -> `Leaves_2026`.
- При открытии проекта:
  - главным источником имени считать `project_path.stem`;
  - если внутри JSON поле `name` отличается от имени файла, синхронизировать `ProjectDocument.name` с `project_path.stem`;
  - при необходимости запланировать сохранение, чтобы JSON стал согласован с именем файла.
- Если имя файла заканчивается на `.json`, расширение в поле `Имя проекта` не показывать.

Правила редактирования `Имя проекта`:
- Пользователь вводит имя без пути и без расширения.
- Если пользователь ввел суффикс `.json`, убрать только этот суффикс.
- Использовать такую же безопасную нормализацию имени файла, как при создании нового проекта, или вынести общую функцию:
  - обрезать пробелы по краям;
  - не принимать пустое имя;
  - не принимать значения с `/` или `\`;
  - не принимать `.` и `..`;
  - привести имя к безопасному имени файла проекта;
  - после нормализации показать в поле фактический stem нового файла.
- Новое имя файла должно быть:
  - `<normalized_project_name>.json`;
  - в той же директории, где лежал старый проектный JSON.
- Переименовывать только JSON-файл проекта.
- Не переименовывать папку проекта, папку `images`, изображения или относительные пути изображений.

Порядок действий при успешном переименовании:
1. Получить старый путь `old_path = self.project_path`.
2. Построить новый путь `new_path = old_path.with_name(f"{new_name}.json")`.
3. Если `new_path` совпадает с `old_path`, просто привести поле к нормализованному виду и ничего не переименовывать.
4. Если `new_path` уже существует, показать предупреждение, вернуть старое имя в поле и не менять состояние проекта.
5. Остановить или учесть pending autosave, чтобы данные не сохранились в старый путь после переименования.
6. Обновить `self.project_document.name = new_name`.
7. Переименовать файл проекта с `old_path` на `new_path`.
8. Обновить `self.project_path = new_path.resolve()`.
9. Сохранить проект уже по новому пути.
10. Обновить поле `Путь`, поле `Имя проекта`, заголовок окна и статусную строку.

Обработка ошибок:
- Если переименование файла не удалось из-за `OSError`, показать понятную ошибку и вернуть прежнее состояние:
  - `self.project_path` остается старым;
  - `self.project_document.name` остается старым;
  - поле `Имя проекта` возвращается к старому stem;
  - поле `Путь` остается старым.
- Если пользователь ввел некорректное имя, показать предупреждение и вернуть старое имя.
- Если целевой файл уже существует, не перезаписывать его.
- Не оставлять ситуацию, где UI показывает новый путь, а `self.project_path` или файл на диске остались старыми.

Состояние без открытого проекта:
- Панель должна вести себя как раньше: показывать сообщение `Создайте или откройте проект.`
- Поля `Имя проекта`, `Путь`, `Количество файлов`, `Общая информация` должны сбрасываться в безопасные значения.
- Редактирование имени проекта недоступно.

Рекомендуемые тестовые сценарии:
1. Порядок строк:
   - `Имя проекта`;
   - `Путь`;
   - `Количество файлов`;
   - `Общая информация`.
2. При открытии файла `actual_name.json`, если в JSON записано `"name": "old_name"`, в панели показывается `actual_name`, `ProjectDocument.name == "actual_name"`.
3. Редактирование `Имя проекта` с `New_Project`:
   - старый файл `old.json` исчезает;
   - новый файл `New_Project.json` появляется;
   - `window.project_path` указывает на новый файл;
   - поле `Путь` показывает новый путь;
   - `ProjectDocument.name == "New_Project"`;
   - JSON в новом файле содержит `"name": "New_Project"`.
4. Редактирование `Имя проекта` с `New_Project.json` дает тот же результат: файл называется `New_Project.json`, в UI показано `New_Project`.
5. После переименования последующие изменения, например `Общая информация`, сохраняются в новый JSON-файл, а не в старый.
6. Если целевой файл уже существует, переименование отклоняется:
   - старый файл не тронут;
   - существующий файл не перезаписан;
   - `project_path` не меняется;
   - поле имени возвращается к старому значению.
7. Пустое имя, `.` / `..`, имя с `/` или `\` отклоняются.
8. Переименование файла проекта не меняет папку проекта и относительные пути изображений.

Ограничения:

- Не добавлять новое поле пути в JSON.
- Не переименовывать изображения и папку проекта.
- Не менять экспорт свойств изображения и экспорт списка проекта, если это не требуется для прохождения тестов.
- Не добавлять новые зависимости.
- Не добавлять CI или portable-сборку в рамках этой задачи.

- Все тесты проходят.
