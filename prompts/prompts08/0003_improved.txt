Задача: исправить поведение панели свойств MagicBorder: при выборе OIV в поле `Оценка` не должна сворачиваться текущая раскрытая нода измерения.

Исходная формулировка:
"Сделай так, чтобы при выборе Оценки не коллапсировала текущая выбранная нода"

Контекст проекта:
- MagicBorder - настольное приложение на Python и `PyQt5`.
- Панель свойств изображения построена на `PropertyBrowser` (`src/magicborder/property_browser.py`), который наследуется от `QTreeWidget`.
- В `src/magicborder/main_window.py` есть дерево свойств изображения:
  - `Измерения`;
  - `Углы`;
  - конкретная нода угла, например `Угол 1` или имя угла;
  - `Отрезки`;
  - конкретная нода отрезка, например `Отрезок 1` или имя отрезка.
- В нодах конкретных углов и отрезков есть строка `Оценка` с `QComboBox` для выбора OIV-признака и строка `Результат оценки`.
- Сейчас при изменении выбора в `Оценка` обработчики:
  - `_handle_angle_assessment_changed`;
  - `_handle_segment_assessment_changed`;
  вызывают `_update_project_properties()`.
- `_update_project_properties()` пересобирает измерения через:
  - `_rebuild_angle_measurement_properties`;
  - `_rebuild_segment_measurement_properties`.
- При пересборке дочерние ноды очищаются, а группы конкретных углов/отрезков создаются с `expanded=False`, поэтому раскрытая пользователем нода схлопывается.

Проблема:
- Пользователь раскрывает ноду конкретного угла или отрезка в панели свойств.
- В строке `Оценка` выбирает OIV-признак.
- После выбора текущая нода измерения сворачивается.
- Это сбивает пользователя: строка `Результат оценки` и остальные свойства измерения исчезают из видимой области, хотя пользователь продолжает работать с тем же измерением.

Главное требование:
- При выборе значения в поле `Оценка` текущая раскрытая нода угла или отрезка должна оставаться раскрытой.
- Родительские ноды `Измерения`, `Углы` и `Отрезки` должны сохранять свое текущее состояние раскрытия.
- Нельзя вместо этого просто раскрывать все дерево целиком: состояния остальных нод должны сохраняться настолько точно, насколько это разумно.
- Выбранный OIV-признак должен по-прежнему сохраняться в модели проекта и автосохранении.
- `Результат оценки` должен обновляться сразу после выбора.

Ожидаемое поведение для угла:
1. Пользователь раскрывает:
   - `Измерения`;
   - `Углы`;
   - конкретный угол, например `Контрольный угол`.
2. В строке `Оценка` выбирает, например, `OIV 607`.
3. Нода `Контрольный угол` остается раскрытой.
4. Строка `Результат оценки` остается видимой и показывает актуальное значение.
5. Выбранный OIV сохраняется в `record.measurements.angles[*].assessment`.

Ожидаемое поведение для отрезка:
1. Пользователь раскрывает:
   - `Измерения`;
   - `Отрезки`;
   - конкретный отрезок, например `Контрольный отрезок`.
2. В строке `Оценка` выбирает, например, `OIV 601`.
3. Нода `Контрольный отрезок` остается раскрытой.
4. Строка `Результат оценки` остается видимой и показывает актуальное значение или статус `Нужна калибровка`.
5. Выбранный OIV сохраняется в `record.measurements.segments[*].assessment`.

Предпочтительный подход:
- Не пересобирать всю панель свойств только из-за выбора OIV, если это не требуется.
- В обработчиках `_handle_angle_assessment_changed` и `_handle_segment_assessment_changed` после изменения `assessment` обновлять только соответствующее поле `Результат оценки`:
  - для угла - `self._angle_assessment_result_fields[angle_id]`;
  - для отрезка - `self._segment_assessment_result_fields[segment_id]`.
- После точечного обновления по-прежнему вызывать `_schedule_project_save()`.
- Такой вариант лучше сохраняет раскрытие дерева, текущую позицию прокрутки и фокус пользователя.

Допустимый альтернативный подход:
- Если по архитектуре удобнее оставить пересборку панели, перед пересборкой нужно сохранить состояние раскрытия дерева по стабильным ключам, а после пересборки восстановить его.
- Использовать стабильные ключи из `Qt.UserRole + 1`, например:
  - `measurements`;
  - `measurements:angles`;
  - `angle:<id>`;
  - `measurements:segments`;
  - `segment:<id>`.
- Не привязываться к отображаемому имени группы, потому что имя угла/отрезка может измениться.
- Восстанавливать только те ключи, которые реально существуют после пересборки.

Требования к реализации:
- Исправить поведение и для углов, и для отрезков.
- Не ломать фильтрацию доступных OIV-признаков:
  - углам доступны только признаки для `angle`;
  - отрезкам доступны только признаки для `segment`.
- Не менять формат JSON проекта без необходимости.
- Не сохранять вычисленную оценку в проект как источник истины.
- Не добавлять внешние зависимости.
- Не менять справочник `oiv_ampelometric_scales.json`, если в нем нет ошибки.
- Не менять смысл существующих действий с видимостью, именем, примечанием и геометрией измерений.
- Не создавать циклы сигналов `QComboBox.currentIndexChanged` при программном обновлении виджета.
- Если используется восстановление состояния дерева, не раскрывать автоматически свернутые пользователем соседние ноды.

Рекомендуемые места изменений:
- `src/magicborder/main_window.py`
  - `_handle_angle_assessment_changed`;
  - `_handle_segment_assessment_changed`;
  - при необходимости вспомогательные методы для точечного обновления результата OIV.
- `src/magicborder/property_browser.py`
  - только если выбран вариант с сохранением/восстановлением раскрытых нод на уровне `PropertyBrowser`.
- `tests/test_project_properties.py`
  - добавить регрессионный тест на сохранение раскрытой ноды при выборе `Оценка`.

Рекомендуемый тест для угла:
- Создать окно с проектом, где есть хотя бы один угол и доступен комбобокс оценки.
- Раскрыть в `properties_browser` ноды:
  - группу `Измерения`;
  - группу `Углы`;
  - группу конкретного угла по ключу `angle:<angle_id>`.
- Через combo выбрать `OIV 607`.
- Проверить:
  - `record.measurements.angles[0].assessment.code == "OIV 607"`;
  - нода `angle:<angle_id>` остается `isExpanded() == True`;
  - родительские ноды остаются раскрытыми;
  - свойство `angle:<angle_id>:assessment_result` видимо через `is_property_visible`;
  - текст результата оценки обновлен.

Рекомендуемый тест для отрезка:
- Создать окно с проектом, где есть хотя бы один отрезок и доступен комбобокс оценки.
- Раскрыть в `properties_browser` ноды:
  - группу `Измерения`;
  - группу `Отрезки`;
  - группу конкретного отрезка по ключу `segment:<segment_id>`.
- Через combo выбрать `OIV 601`.
- Проверить:
  - `record.measurements.segments[0].assessment.code == "OIV 601"`;
  - нода `segment:<segment_id>` остается `isExpanded() == True`;
  - родительские ноды остаются раскрытыми;
  - свойство `segment:<segment_id>:assessment_result` видимо через `is_property_visible`;
  - текст результата оценки обновлен или показывает корректный статус при отсутствии калибровки.

Проверки перед завершением:
- Выбор `Оценка` у раскрытого угла не сворачивает ноду угла.
- Выбор `Оценка` у раскрытого отрезка не сворачивает ноду отрезка.
- Результат оценки обновляется сразу.
- Выбор сохраняется в модели проекта.
- Автосохранение по-прежнему планируется.
- Соседние ноды не раскрываются и не сворачиваются неожиданно.
- Старые тесты OIV и свойств проекта продолжают проходить.
- Запустить тесты:
  - `uv run pytest tests/test_project_properties.py tests/test_project_models.py tests/test_oiv_classifier.py`
  - при возможности полный набор: `uv run pytest`

Критерии готовности:
- Пользователь может раскрыть конкретный угол или отрезок, выбрать OIV в строке `Оценка` и сразу увидеть результат, оставаясь в той же раскрытой ноде панели свойств.
- Исправление покрыто регрессионным тестом для углов и отрезков.
- Поведение панели свойств стало стабильнее без лишней пересборки UI или с корректным восстановлением состояния дерева.
