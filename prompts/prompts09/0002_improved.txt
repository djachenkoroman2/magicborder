Задача: добавить настраиваемый цвет линии для главного контура, каждого угла и каждого отрезка, дать пользователю возможность выбирать цвет из панели `Свойства изображения` и сохранять выбранные значения в JSON.

Исходная формулировка:
"Для главного контура, углов и отрезков необходимо добавить свойство цвет линии.
В окне свойств для соответствуующего объекта предусмотреть вызов диалога выбора цвета.
Данные свойства также необходимо хранить в json."

Контекст проекта:
- MagicBorder - настольное приложение на Python и `PyQt5`.
- Модели проекта и JSON-сериализация находятся в `src/magicborder/models.py`.
- Канвас и графические элементы находятся в `src/magicborder/canvas.py`.
- Панель `Свойства изображения` и синхронизация модели с канвасом находятся в `src/magicborder/main_window.py`.
- Для панели свойств используется `PropertyBrowser` из `src/magicborder/property_browser.py`.
- Главный контур рисуется через `ImageCanvas._path_item`.
- Угол представлен:
  - моделью проекта `ProjectAngleMeasurement`;
  - моделью канваса `AngleMeasurement`;
  - графикой `AngleGraphics`, содержащей два луча, дугу, подпись и handles.
- Отрезок представлен:
  - моделью проекта `ProjectSegmentMeasurement`;
  - моделью канваса `SegmentMeasurement`;
  - графикой `SegmentGraphics`.
- Сейчас цвета заданы константами в `canvas.py`:
  - главный контур: `CONTOUR_LINE_COLOR = "#0b84c6"`;
  - лучи угла: `ANGLE_LINE_COLOR = "#22c55e"`;
  - дуга угла: `ANGLE_ARC_COLOR = "#7c3aed"`;
  - отрезок: `SEGMENT_LINE_COLOR = "#f97316"`.
- Измерения углов и отрезков уже сохраняются в группе `measurements` JSON-файла проекта.
- Главный контур сохраняется как `Annotation`, вложенная в `contour.annotation`, и может отдельно экспортироваться/импортироваться как JSON-аннотация.

Цель:
- У главного контура должно быть собственное свойство `Цвет линии`.
- У каждого отдельного угла должно быть собственное свойство `Цвет линии`.
- У каждого отдельного отрезка должно быть собственное свойство `Цвет линии`.
- Цвет выбирается стандартным диалогом `QColorDialog`.
- Изменение цвета сразу отображается на канвасе без перезагрузки изображения.
- Выбранные цвета сохраняются в JSON и восстанавливаются при повторном открытии проекта или аннотации.
- Старые JSON-файлы без новых полей продолжают корректно открываться и используют текущие цвета по умолчанию.

Формат цвета:
- Во всех моделях и JSON хранить цвет как строку в каноническом формате `#rrggbb`.
- Использовать непрозрачный RGB-цвет без alpha-канала.
- После выбора через `QColorDialog` нормализовать значение, например к нижнему регистру:
  - `#0b84c6`;
  - `#22c55e`;
  - `#f97316`.
- Для проверки строк из JSON использовать `QColor` или отдельный helper с эквивалентной строгой проверкой.
- Пустое, отсутствующее или некорректное значение цвета не должно ломать загрузку проекта, аннотации или отдельного измерения: использовать соответствующий цвет по умолчанию.
- Не допускать сохранения произвольных строк, которые `QColor` не распознаёт как валидный цвет.

Цвета по умолчанию:
- главный контур: `#0b84c6`;
- лучи угла: `#22c55e`;
- отрезок: `#f97316`.
- Старые проекты без `line_color` должны визуально выглядеть так же, как до этой доработки.
- Новые контуры, углы и отрезки должны создаваться с этими же значениями.
- Желательно определить значения по умолчанию в одном месте, доступном моделям и канвасу, без циклических импортов и дублирования расходящихся констант.

Модель данных и JSON:

1. Главный контур
- Добавить `line_color` в `Annotation`, потому что цвет является свойством конкретного главного контура и должен сохраняться как:
  - внутри JSON проекта в `images[].contour.annotation`;
  - в отдельном JSON-файле аннотации при действии сохранения аннотации.
- `Annotation.from_dict(...)` должен подставлять цвет главного контура по умолчанию, если поле отсутствует или некорректно.
- `Annotation.to_dict()` должен записывать нормализованное поле `line_color`.
- При удалении главного контура вместе с аннотацией удаляется и его индивидуальный цвет.
- Новый контур, созданный после полного удаления старого, получает цвет по умолчанию.
- Обычное редактирование геометрии существующего контура, автоматическое переопределение его точек или сохранение текущей аннотации не должно случайно сбрасывать уже выбранный цвет.

Пример фрагмента JSON проекта:
```json
{
  "contour": {
    "annotation": {
      "version": 1,
      "image_path": "images/leaf.png",
      "image_size": {
        "width": 1200,
        "height": 800
      },
      "closed": true,
      "points": [
        {"x": 10.0, "y": 20.0}
      ],
      "line_color": "#0b84c6"
    }
  }
}
```

2. Углы
- Добавить поле `line_color` в `ProjectAngleMeasurement`.
- Добавить соответствующее поле в канвас-модель `AngleMeasurement`.
- `ProjectAngleMeasurement.to_dict()` должен сохранять `line_color`.
- `ProjectAngleMeasurement.from_dict()` должен читать и нормализовать `line_color`, используя `#22c55e` при отсутствии или ошибке.
- Цвет индивидуален: изменение цвета одного угла не должно менять остальные углы.

Пример:
```json
{
  "id": "angle-1",
  "name": "Контрольный угол",
  "first": {"x": 2.0, "y": 10.0},
  "vertex": {"x": 2.0, "y": 2.0},
  "second": {"x": 10.0, "y": 2.0},
  "line_color": "#16a34a",
  "note": ""
}
```

3. Отрезки
- Добавить поле `line_color` в `ProjectSegmentMeasurement`.
- Добавить соответствующее поле в канвас-модель `SegmentMeasurement`.
- `ProjectSegmentMeasurement.to_dict()` должен сохранять `line_color`.
- `ProjectSegmentMeasurement.from_dict()` должен читать и нормализовать `line_color`, используя `#f97316` при отсутствии или ошибке.
- Цвет индивидуален: изменение цвета одного отрезка не должно менять остальные отрезки.

Пример:
```json
{
  "id": "segment-1",
  "name": "Контрольный отрезок",
  "start": {"x": 10.0, "y": 20.0},
  "end": {"x": 80.0, "y": 20.0},
  "line_color": "#ea580c",
  "start_label": "A",
  "end_label": "B",
  "note": ""
}
```

Совместимость JSON:
- Новые поля должны быть необязательными при чтении.
- Не отбрасывать корректные углы, отрезки или аннотации только из-за отсутствующего/невалидного `line_color`.
- Сохранять существующее поведение `extra_groups` и неизвестных полей.
- Повышать `PROJECT_FORMAT_VERSION` необязательно, если новые поля реализованы как обратно совместимые необязательные поля.
- После открытия старого проекта и последующего сохранения допустимо записать в него явные значения `line_color` по умолчанию.

Панель `Свойства изображения`:

1. Главный контур
- В группе `Информация о главном контуре` добавить строку `Цвет линии`.
- Рекомендуемый порядок:
```text
Аннотация
Показывать контур
Цвет линии
Количество узлов контура
Количество пикселов контура
Площадь контура, мм²
```
- Использовать ключ свойства `contour:line_color`.
- Поле выбора цвета должно быть доступно только при наличии валидного главного контура у текущего изображения.

2. Каждый угол
- В динамической группе каждого угла добавить строку `Цвет линии`.
- Рекомендуемый порядок:
```text
Имя
Показывать на канвасе
Цвет линии
ID
Значение
...
```
- Использовать ключ `angle:<angle_id>:line_color`.

3. Каждый отрезок
- В динамической группе каждого отрезка добавить строку `Цвет линии`.
- Рекомендуемый порядок:
```text
Имя
Показывать на канвасе
Цвет линии
ID
Длина
...
```
- Использовать ключ `segment:<segment_id>:line_color`.

Виджет выбора цвета:
- В значении свойства разместить компактную кнопку или небольшой составной виджет.
- Виджет должен одновременно показывать:
  - образец текущего цвета;
  - текстовое значение `#rrggbb`.
- По нажатию открывать `QColorDialog` с текущим цветом в качестве начального.
- Диалог должен иметь понятный заголовок, например:
  - `Цвет линии главного контура`;
  - `Цвет линии угла`;
  - `Цвет линии отрезка`.
- Если пользователь отменил диалог, ничего не менять:
  - модель;
  - канвас;
  - JSON;
  - состояние autosave.
- После подтверждения:
  - обновить виджет свойства;
  - обновить соответствующий графический объект на канвасе;
  - обновить модель проекта;
  - запустить существующий механизм отложенного автосохранения.
- Не открывать отдельный диалог ручного ввода HEX, если стандартного `QColorDialog` достаточно.

Поведение канваса:

Главный контур:
- `ImageCanvas` должен хранить текущий цвет линии контура.
- Добавить явный API для чтения и изменения цвета, например:
  - `contour_line_color()`;
  - `set_contour_line_color(color_name)`.
- При изменении цвета обновлять pen у `_path_item`.
- `_apply_contour_highlight()` должен менять только толщину и z-order, сохраняя выбранный цвет.
- После снятия подсветки выбранный пользователем цвет не должен заменяться на `CONTOUR_LINE_COLOR`.

Угол:
- Два луча конкретного угла должны рисоваться его `line_color`.
- Свойство `Цвет линии` относится именно к двум лучам угла.
- Дуга должна сохранять отдельный контрастный цвет `ANGLE_ARC_COLOR`, чтобы не нарушать существующее требование отличать дугу от лучей.
- Цвет handles, вершины и текстовой подписи в эту задачу не входит.
- Добавить API чтения/изменения цвета конкретного угла по ID, например:
  - `angle_measurement_line_color(angle_id)`;
  - `set_angle_measurement_line_color(angle_id, color_name)`.
- `_create_angle_graphic`, `_refresh_angle_graphic` и `_apply_angle_highlight` должны использовать цвет из `AngleMeasurement`.
- Подсветка угла должна менять толщину/z-order, но не цвет.
- Изменение имени, геометрии, видимости или пересоздание графики угла не должно сбрасывать его цвет.

Отрезок:
- Линия конкретного отрезка должна рисоваться его `line_color`.
- Цвет handles и текстовых подписей в эту задачу не входит.
- Добавить API чтения/изменения цвета конкретного отрезка по ID, например:
  - `segment_measurement_line_color(segment_id)`;
  - `set_segment_measurement_line_color(segment_id, color_name)`.
- `_create_segment_graphic`, `_refresh_segment_graphic` и `_apply_segment_highlight` должны использовать цвет из `SegmentMeasurement`.
- Подсветка отрезка должна менять толщину/z-order, но не цвет.
- Изменение имени, подписей точек, геометрии, видимости или пересоздание графики не должно сбрасывать цвет.

Preview новых измерений:
- Preview во время создания нового угла или отрезка может использовать существующий цвет по умолчанию.
- После завершения измерения созданный объект также получает цвет по умолчанию.
- Не требуется добавлять глобальную настройку цвета будущих измерений.

Не входит в задачу:
- Не добавлять настройку цвета калибровочного отрезка.
- Не добавлять настройку цвета узлов/handles.
- Не менять цвет подписей углов, длин и точек отрезков.
- Не добавлять отдельную настройку цвета дуги угла.
- Не менять толщину линий, кроме уже существующей логики подсветки.
- Не менять геометрию, расчёты углов, длин, площадей, гистограмм и OIV-оценок.
- Не сохранять видимость объектов в JSON: существующее поведение для `visible` оставить без изменений.
- Не добавлять `Цвет линии` в Excel-экспорт свойств изображения или списка проекта: это визуальная настройка, а исходная задача требует только UI и JSON.
- Не менять структуру групп `Цветовые пространства`.

Критерии приёмки:
1. В группе `Информация о главном контуре` есть свойство `Цвет линии`, открывающее `QColorDialog`.
2. В группе каждого угла есть собственное свойство `Цвет линии`.
3. В группе каждого отрезка есть собственное свойство `Цвет линии`.
4. Виджет свойства показывает образец цвета и его значение `#rrggbb`.
5. После подтверждения диалога цвет соответствующей линии меняется сразу.
6. Отмена диалога не изменяет состояние и не запускает сохранение.
7. Цвет одного угла или отрезка не влияет на другие измерения.
8. Пользовательский цвет сохраняется при подсветке, снятии подсветки, drag, переименовании, скрытии/показе и перестроении графики.
9. У угла выбранный цвет применяется к двум лучам, а дуга остаётся отдельного контрастного цвета.
10. Цвет главного контура сохраняется в JSON-аннотации.
11. Цвета углов и отрезков сохраняются в соответствующих элементах `measurements` JSON-проекта.
12. После сохранения и повторного открытия проекта все цвета восстанавливаются.
13. Отдельно сохранённая и повторно открытая аннотация восстанавливает цвет главного контура.
14. Старые проекты и аннотации без `line_color` открываются с прежними цветами по умолчанию.
15. Некорректный цвет в JSON не приводит к падению или потере всего объекта.
16. Существующие сценарии создания, редактирования, выделения, видимости, удаления и сохранения объектов продолжают работать.
17. Все существующие и новые тесты проходят в offscreen-режиме.
