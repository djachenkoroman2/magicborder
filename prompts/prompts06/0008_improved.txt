Задача: добавить порядковый номер угла в подписи измерений на канвасе и обеспечить обновление подписей при изменении коллекции углов.

Контекст:
- Проект MagicBorder - настольное приложение на PyQt5.
- Инструмент измерения углов реализован в `src/magicborder/canvas.py`.
- Угол задаётся тремя точками:
  - первая точка луча;
  - вершина;
  - вторая точка луча.
- Графика угла описана dataclass `AngleGraphics`.
- Сейчас у завершённого угла на канвасе отображаются:
  - два отрезка;
  - дуга;
  - три draggable-узла;
  - текстовая подпись значения угла в градусах.
- Подпись задаётся в `_refresh_angle_graphic` через `graphics.label.setPlainText(...)`.
- Сейчас подпись содержит только значение, например `90°`.
- Углы уже являются коллекцией измерений:
  - в `ImageCanvas` есть `_angle_measurements: list[AngleMeasurement]`;
  - для проектных сущностей есть стабильный `id`;
  - в панели "Свойства изображения" углы отображаются как "Угол 1", "Угол 2" и так далее.
- Нужно, чтобы номер в подписи на канвасе соответствовал порядковому номеру угла в текущей коллекции и совпадал с номером в панели свойств.

Область изменений:
- `src/magicborder/canvas.py`:
  - формирование текста подписи угла;
  - обновление подписей при пересборке, удалении, добавлении, загрузке и изменении углов;
  - при необходимости небольшой helper для форматирования подписи.
- `src/magicborder/main_window.py`, только если требуется синхронизировать порядок/пересборку коллекции между моделью, панелью свойств и канвасом.
- Тесты в `tests/test_canvas.py` и, при необходимости, `tests/test_project_properties.py`.

Не входит в задачу:
- Не менять способ создания угла тремя кликами.
- Не менять расчёт численного значения угла в градусах.
- Не менять геометрию угла, дуги, линий и draggable-узлов.
- Не менять формат хранения углов в JSON.
- Не менять стабильные `id` углов.
- Не добавлять новые типы измерений.
- Не менять порядок углов в модели без необходимости.
- Не менять UI панели свойств, кроме случаев, когда это требуется для согласованности нумерации.

Требования к подписи на канвасе:
- Вместо подписи вида:
  - `90°`
  нужно показывать:
  - `Угол 1: 90°`
  - `Угол 2: 45°`
  - `Угол 3: 120°`
- Номер угла должен быть порядковым номером в текущей коллекции углов, начиная с `1`.
- Номер на канвасе должен совпадать с заголовком соответствующей группы в панели свойств:
  - группа `Угол 1` -> подпись `Угол 1: ...`;
  - группа `Угол 2` -> подпись `Угол 2: ...`.
- Стабильный `id` угла не должен использоваться как видимый номер в подписи.
- Если значение угла невозможно вычислить, подпись должна сохранять номер и показывать пустое/невалидное значение в текущем стиле, например:
  - `Угол 1: -`
- Формат численного значения после двоеточия должен остаться прежним:
  - округление;
  - знак градуса;
  - обработка `None`.
- Рекомендуется вынести форматирование в helper, например:
  - `_format_angle_label(angle_index: int, angle_degrees: float | None) -> str`;
  - внутри использовать существующий `_format_angle_degrees`.

Требования к обновлению коллекции:
- Подписи должны обновляться при любом изменении коллекции углов:
  - создание нового угла третьим кликом;
  - загрузка углов через `set_angle_measurements`;
  - загрузка проектных углов через `set_angle_measurement_records`;
  - удаление выбранного угла с канваса;
  - удаление угла из панели свойств, если оно пересобирает canvas-коллекцию;
  - `clear_angles`;
  - переключение изображения;
  - открытие проекта с сохранёнными углами.
- После удаления угла оставшиеся углы должны быть перенумерованы без пропусков:
  - если были `Угол 1`, `Угол 2`, `Угол 3`;
  - и удалили `Угол 2`;
  - на канвасе должны остаться `Угол 1` и `Угол 2`, а не `Угол 1` и `Угол 3`.
- После добавления нового угла он должен получить следующий порядковый номер в текущей коллекции.
- При перемещении любого узла угла:
  - значение в подписи должно пересчитаться;
  - номер должен остаться тем же, если порядок коллекции не менялся.
- При пересборке графики через `_rebuild_angle_graphics` подписи должны выставляться заново с актуальными номерами.
- При изменении масштаба/размера view, если вызывается `_refresh_angle_labels`, подписи должны сохранять формат `Угол N: значение`.

Требования к синхронизации с моделью и панелью свойств:
- Источником номера должен быть текущий порядок коллекции углов, а не `id`.
- Если порядок в `record.measurements.angles` используется для панели свойств, canvas должен получать углы в том же порядке.
- При сохранении и загрузке проекта порядок углов должен сохраняться, чтобы после открытия подписи и группы панели свойств соответствовали друг другу.
- Редактирование примечания угла не должно менять номер или порядок углов.
- Удаление угла из панели свойств должно обновлять:
  - модель проекта;
  - canvas;
  - подписи оставшихся углов;
  - группы "Угол N" в панели свойств.
- Удаление угла с канваса должно обновлять:
  - canvas;
  - модель проекта;
  - подписи оставшихся углов;
  - группы "Угол N" в панели свойств.

Рекомендации по реализации:
- В `_refresh_angle_graphic(angle_index)` использовать `angle_index + 1` как видимый номер угла.
- Заменить текущую установку текста:
  - `graphics.label.setPlainText(_format_angle_degrees(...))`
  на формат с номером:
  - `graphics.label.setPlainText(_format_angle_label(angle_index, angle_degrees))`.
- Не хранить видимый номер внутри `AngleMeasurement`, потому что он вычисляется из позиции в коллекции.
- Не менять `AngleMeasurement.id`: он нужен для связи с проектной сущностью и JSON.
- Убедиться, что `_rebuild_angle_graphics` создаёт графику в порядке `_angle_measurements`.
- Если удаление или загрузка углов пересобирает список, достаточно вызвать существующее обновление/пересборку графики, но тест должен зафиксировать, что подписи перенумеровались.
- Если есть отдельные helper'ы для текста значения угла в `main_window.py`, не смешивать их с canvas-подписью без необходимости: в панели свойств поле "Значение" может оставаться просто `90°`, а номер уже виден в заголовке группы `Угол N`.

Требования к тестам:
- Обновить тест создания угла в `tests/test_canvas.py`:
  - после третьего клика ожидать подпись `Угол 1: 90°`, а не `90°`.
- Добавить или обновить тест для нескольких углов:
  - установить две или три записи через `set_angle_measurements` или `set_angle_measurement_records`;
  - проверить подписи `Угол 1: ...`, `Угол 2: ...`, `Угол 3: ...`.
- Добавить проверку перенумерации после удаления:
  - создать минимум два угла;
  - удалить первый или второй через выбранную вершину;
  - проверить, что оставшиеся подписи перенумерованы без пропусков.
- Добавить проверку изменения геометрии:
  - переместить узел через `angle_handle_moved`;
  - проверить, что значение изменилось, а номер остался прежним, например `Угол 1: 45°`.
- Если есть UI-тесты панели свойств с сохранёнными углами:
  - проверить, что заголовки `Угол N` в панели соответствуют подписям на канвасе после загрузки проекта;
  - проверить, что удаление из панели обновляет canvas-подписи.
- Тесты не должны требовать видимого GUI-окна; использовать существующий offscreen-подход.

Критерии приёмки:
- На канвасе каждый завершённый угол подписан в формате `Угол N: значение`.
- Нумерация начинается с `1`.
- Номер в подписи соответствует порядку угла в коллекции и группе "Угол N" в панели свойств.
- После добавления, удаления, загрузки, очистки и переключения изображения подписи не устаревают.
- После удаления углов нумерация оставшихся углов не содержит пропусков.
- При перемещении узлов значение угла обновляется, а номер остаётся корректным.
- Стабильные `id` углов и JSON-структура проекта не меняются.
- Существующие сценарии создания, редактирования, удаления, сохранения и загрузки углов продолжают работать.
- Существующие тесты проходят; тесты подписи углов обновлены под новый формат.
