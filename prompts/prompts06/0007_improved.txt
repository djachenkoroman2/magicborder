Задача: сделать измерения углов проектными сущностями, сохраняемыми в JSON, и отобразить их в панели "Свойства изображения" в группе "Измерения".

Контекст:
- Проект MagicBorder - настольное приложение на PyQt5.
- Основные данные проекта описаны в `src/magicborder/models.py`.
- Сохранение/загрузка проекта выполняются через `src/magicborder/io_utils.py` и методы `to_dict` / `from_dict` моделей.
- Правая панель "Свойства изображения" строится в `src/magicborder/main_window.py` через `PropertyBrowser` из `src/magicborder/property_browser.py`.
- Текущий порядок групп панели уже включает:
  - "Общая информация о файле";
  - "Калибровка";
  - "Информация о главном контуре";
  - цветовые группы;
  - "Локация";
  - "Дополнительно".
- Инструмент измерения угла уже реализован на канвасе в `src/magicborder/canvas.py`.
- Сейчас углы являются временными данными сессии:
  - в `MainWindow` есть `_angle_measurements_by_image_id: dict[str, list[tuple[Point, Point, Point]]]`;
  - углы не сохраняются в JSON проекта;
  - в тестах есть сценарий, который прямо проверяет, что углы session-scoped и не сохраняются.
- Новое требование меняет это поведение: углы должны стать сохраняемыми сущностями изображения проекта.

Область изменений:
- Модели проекта в `src/magicborder/models.py`.
- Загрузка/сохранение проекта через существующие `to_dict` / `from_dict`.
- Связь `MainWindow` с канвасом для создания, обновления, удаления и выбора измерений.
- Панель "Свойства изображения" и, при необходимости, возможности `PropertyBrowser` для вложенных динамических групп.
- Тесты моделей проекта, канваса и UI-сценариев в `tests`.

Не входит в задачу:
- Не добавлять новые типы измерений, кроме углов.
- Не менять способ создания угла тремя кликами.
- Не менять визуальный стиль угла на канвасе, если это не нужно для связи с сохранённой сущностью.
- Не менять расчёт значения угла в градусах.
- Не менять структуру контура, калибровки, цветовых свойств, локации и дополнительных сведений.
- Не ломать старые проекты без блока `measurements`.

Требования к модели данных:
- Добавить проектную модель измерений изображения, рассчитанную на расширение новыми типами измерений в будущем.
- Рекомендуемая JSON-структура внутри записи изображения:
  ```json
  {
    "measurements": {
      "angles": [
        {
          "id": "angle-...",
          "first": {"x": 10.0, "y": 20.0},
          "vertex": {"x": 10.0, "y": 10.0},
          "second": {"x": 20.0, "y": 10.0},
          "note": ""
        }
      ]
    }
  }
  ```
- У каждого угла должен быть стабильный `id`, сохраняемый в JSON.
- Геометрия угла должна хранить три точки:
  - `first`;
  - `vertex`;
  - `second`.
- У каждого угла должно быть редактируемое текстовое поле `note` / "Примечание".
- Если блок `measurements` отсутствует в старом проекте, загрузка должна создавать пустую коллекцию измерений.
- Если список `angles` отсутствует, он считается пустым.
- Если в `measurements` есть будущие неизвестные ключи, по возможности сохранить их при round-trip, чтобы будущие типы измерений не терялись.
- Некорректные углы в JSON не должны ломать загрузку всего проекта:
  - либо пропускать только некорректный угол с понятным статусом;
  - либо сохранять raw payload аналогично подходу с повреждённой калибровкой, если это лучше вписывается в текущую модель.

Требования к панели "Свойства изображения":
- Добавить в панель "Свойства изображения" группу верхнего уровня "Измерения".
- Группа "Измерения" должна располагаться сразу после группы "Информация о главном контуре".
- Внутри группы "Измерения" создать подгруппу "Углы".
- Подгруппа "Углы" должна быть динамической коллекцией углов текущего выбранного изображения.
- Если углов нет, подгруппа "Углы" должна показывать понятное пустое состояние, например "Нет углов", или оставаться пустой без ошибок.
- После создания угла на канвасе в "Измерения" -> "Углы" должен появиться элемент соответствующего угла.
- Каждый элемент угла должен быть вложенной подгруппой, например:
  - "Угол 1";
  - "Угол 2";
  - или "Угол <короткий id>", если это лучше для стабильности.
- Внутри каждого элемента угла отобразить основные поля:
  - ID угла;
  - значение угла в градусах;
  - координаты первой точки;
  - координаты вершины;
  - координаты второй точки;
  - "Примечание" как редактируемое поле.
- Значение угла в градусах должно обновляться при изменении геометрии угла.
- Координаты должны обновляться при перемещении узлов угла на канвасе.
- Поле "Примечание" должно сохраняться в JSON проекта.
- Редактирование "Примечание" должно запускать обычный механизм сохранения проекта или автосохранения, как другие редактируемые свойства изображения.

Требования к управлению коллекцией:
- В подгруппе "Углы" предусмотреть команды управления элементами коллекции.
- Минимально необходимая команда: удалить угол.
- Желательно предусмотреть команду выбора/фокусировки угла на канвасе, если это хорошо ложится на текущий UI.
- Удаление угла из панели свойств должно:
  - удалить сущность из модели проекта;
  - удалить графику угла с канваса, если это текущее изображение;
  - обновить список углов в группе "Углы";
  - обновить доступность action "Удалить угол";
  - запланировать сохранение проекта.
- Удаление угла с канваса через существующее действие "Удалить угол" должно:
  - удалить ту же проектную сущность;
  - обновить группу "Измерения" -> "Углы";
  - запланировать сохранение проекта.
- Нельзя удалять или менять контур, калибровку или другие элементы при удалении угла.

Требования к синхронизации канваса и модели:
- После создания угла тремя кликами:
  - создать проектную сущность угла с новым стабильным `id`;
  - записать её в измерения текущего `ProjectImageRecord`;
  - отобразить её в панели "Измерения" -> "Углы";
  - запланировать сохранение проекта.
- При перемещении любого узла угла:
  - обновить геометрию соответствующей проектной сущности;
  - пересчитать значение угла;
  - обновить поля панели свойств;
  - запланировать сохранение проекта.
- При переключении изображений:
  - на канвасе должны отображаться углы выбранного изображения из модели проекта;
  - в панели "Измерения" -> "Углы" должны отображаться только углы выбранного изображения;
  - углы предыдущего изображения должны скрываться.
- При закрытии и повторном открытии проекта углы должны восстановиться из JSON.
- Старую временную структуру `_angle_measurements_by_image_id` нужно либо удалить, либо заменить мостом к модели проекта; она больше не должна быть источником истины.
- Важно сохранить связь между графическим углом на канвасе и проектной сущностью:
  - через `id`;
  - либо через индекс, если индекс стабилен при текущих операциях;
  - предпочтительно через `id`, чтобы будущие операции сортировки и удаления не ломали привязку.

Требования к `PropertyBrowser`:
- Если текущий `PropertyBrowser` умеет только top-level группы и плоские свойства, расширить его минимально и аккуратно:
  - добавить возможность создавать вложенные группы/подгруппы;
  - добавить динамическую очистку/пересборку группы "Измерения" или "Углы";
  - сохранить существующее поведение старых групп и тестов.
- Вложенные группы должны корректно сворачиваться/разворачиваться.
- Поиск `property_item` по ключам не должен конфликтовать между углами; для динамических полей использовать уникальные ключи, например `angle:<id>:note`.
- Не допускать утечек старых `QWidget`/items при пересборке динамической коллекции.

Требования к будущему расширению измерений:
- Структура модели и UI должна позволять позже добавить другие типы измерений, например длины, площади, маркеры или произвольные сегменты.
- Не хардкодить "Измерения" так, чтобы она могла содержать только углы.
- Не смешивать измерения с группами "Калибровка", "Информация о главном контуре" и "Дополнительно".
- В JSON блока `measurements` использовать отдельные коллекции по типам, например `angles`, чтобы позже добавить `segments` или `markers`.

Критерии приёмки:
- В панели "Свойства изображения" появилась группа "Измерения" сразу после "Информация о главном контуре".
- В группе "Измерения" есть подгруппа "Углы".
- После создания угла на канвасе в "Углы" появляется элемент этого угла.
- Элемент угла показывает основные поля: ID, значение в градусах, три точки и "Примечание".
- "Примечание" редактируется и сохраняется в JSON проекта.
- Углы сохраняются в JSON проекта в блоке `measurements.angles`.
- После закрытия и повторного открытия проекта углы восстанавливаются на канвасе и в панели свойств.
- При переключении изображений отображаются только углы выбранного изображения.
- При перемещении узлов угла обновляются canvas, модель проекта и панель свойств.
- При удалении угла из панели или с канваса удаляется одна и та же проектная сущность.
- Старые проекты без `measurements` открываются без ошибок.
- Существующие сценарии контура, калибровки, экспорта и цветовых свойств продолжают работать.
- Тесты проекта проходят; старый тест "углы не сохраняются" заменён на тест нового поведения.
