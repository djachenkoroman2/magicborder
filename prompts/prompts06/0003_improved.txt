Задача: реализовать вспомогательный инструмент измерения углов на канвасе.

Контекст:
- Приложение отображает выбранное изображение на канвасе и уже умеет работать с интерактивными графическими элементами: контуром, узлами, калибровочным отрезком и подписями.
- Нужно добавить временный инструмент измерения углов в градусах.
- Это вспомогательный инструмент текущей сессии: результаты измерений не сохраняются в JSON проекта и не экспортируются.
- Измеренные углы должны отображаться на канвасе только для конкретного выбранного изображения во время работы программы.

Область изменений:
- Панель инструментов и/или меню действий.
- Канвас изображения и режимы взаимодействия с ним.
- Состояние временных измерений углов для выбранного изображения.
- Отрисовка точек, лучей, дуги или линий угла и подписи значения.
- Перетаскивание узлов угла и динамическое обновление значения.
- Удаление выбранного измеренного угла.
- Тесты поведения канваса и UI-состояний, если в проекте есть подходящая инфраструктура.

Требования к пользовательскому сценарию:
- На панели инструментов должна появиться кнопка или действие "Угол".
- После активации инструмента пользователь задаёт угол тремя кликами по канвасу:
  - первый клик задаёт точку, через которую проходит первый луч;
  - второй клик задаёт вершину угла;
  - третий клик задаёт точку, через которую проходит второй луч.
- После третьего клика на канвасе должен появиться измеренный угол:
  - три узла;
  - два луча или два отрезка от вершины к точкам лучей;
  - значение угла в градусах.
- Значение угла должно отображаться рядом с вершиной, предпочтительно немного выше неё, если это не конфликтует с видимостью.
- Пользователь должен иметь возможность создать угол для выбранного изображения, затем переключиться на другой инструмент без потери уже нанесённого временного измерения.
- Если пользователь переключается между изображениями, на канвасе должны отображаться только временные углы текущего выбранного изображения.
- При закрытии проекта или выходе из приложения временные углы не сохраняются.

Требования к динамике ввода:
- Во время создания угла состояние инструмента должно быть визуально понятным.
- После первого клика нужно отобразить первый узел и подсказку следующего шага.
- Пока пользователь двигает мышь после первого клика, можно показывать временную линию от первой точки к текущей позиции курсора как предварительную подсказку.
- После второго клика нужно:
  - отобразить вершину угла;
  - отобразить первый луч или отрезок от вершины к первой точке;
  - показывать временный второй луч от вершины к текущей позиции курсора.
- После третьего клика временные элементы должны превратиться в постоянное измерение угла текущей сессии.
- Если пользователь нажимает `Esc`, правую кнопку мыши или выбирает другой инструмент до завершения трёх кликов, незавершённое измерение должно быть отменено без создания угла.
- Клики вне изображения должны игнорироваться или приводиться к допустимой области в стиле существующего канваса.

Требования к расчёту:
- Угол рассчитывается по трём точкам:
  - `p1`: точка первого луча;
  - `vertex`: вершина угла;
  - `p2`: точка второго луча.
- Использовать угол между векторами `vertex -> p1` и `vertex -> p2`.
- Значение должно отображаться в градусах.
- По умолчанию показывать меньший угол между лучами в диапазоне от `0` до `180` градусов.
- Если одна из точек лучей совпадает с вершиной или находится слишком близко к ней, угол считать некорректным и не создавать завершённое измерение.
- Формат подписи должен быть читаемым:
  - например `45°`;
  - `45.5°`;
  - `120°`.
- Не показывать длинный хвост float.

Требования к редактированию:
- Узлы измеренного угла должны быть перетаскиваемыми.
- При перемещении любой из трёх точек:
  - геометрия лучей обновляется;
  - значение угла пересчитывается;
  - подпись угла обновляется;
  - подпись остаётся рядом с вершиной.
- Узлы угла должны быть визуально отличимы от узлов контура и узлов калибровки.
- Редактирование узлов угла не должно менять контур изображения, калибровку, метаданные и JSON проекта.
- Если угол становится некорректным из-за перетаскивания точки слишком близко к вершине, нужно либо ограничить перемещение, либо показать понятное состояние без падения приложения.

Требования к удалению:
- Нужно предусмотреть действие или кнопку "Удалить угол".
- Удаление должно быть доступно только тогда, когда выбран центральный узел, то есть вершина одного из измеренных углов.
- Если выбран центральный узел угла и пользователь нажимает "Удалить угол", удаляется всё измерение угла целиком: три узла, линии и подпись.
- Если вершина угла не выбрана, действие "Удалить угол" должно быть недоступно или ничего не делать с понятным статусным сообщением.
- Удаление угла не должно удалять узлы контура, калибровку или другие элементы канваса.

Требования к визуализации:
- Измеренный угол должен быть виден поверх изображения, но не должен визуально спорить с контуром и калибровкой.
- Для угла использовать отдельный цвет и стиль, например зелёный, фиолетовый или другой цвет, которого нет у контура и калибровки.
- Узел вершины должен отличаться от двух точек лучей, например размером, цветом или обводкой.
- Линии угла должны быть аккуратными и косметическими, чтобы толщина оставалась стабильной при масштабировании.
- Подпись угла должна оставаться читаемой при масштабировании канваса.
- При необходимости можно добавить небольшую дугу у вершины, но это не обязательно, если два луча и подпись уже ясно показывают измерение.

Требования к состоянию и жизненному циклу:
- Измерения углов являются временными и живут только в памяти приложения.
- В JSON проекта не нужно добавлять новые поля для углов.
- Автосохранение проекта не должно запускаться только из-за создания, редактирования или удаления временного угла.
- Углы должны быть привязаны к изображению в рамках текущей сессии:
  - при выборе изображения показываются его временные углы;
  - при выборе другого изображения углы предыдущего изображения скрываются;
  - при возврате к изображению в той же сессии его временные углы снова отображаются, если они ещё хранятся в памяти.
- При удалении изображения из проекта или закрытии проекта связанные временные углы должны очищаться.

Требования к UX:
- У инструмента должны быть подсказки в status bar или tooltip, объясняющие следующий шаг:
  - "Укажите точку первого луча";
  - "Укажите вершину угла";
  - "Укажите точку второго луча".
- Пользователь должен понимать, находится ли сейчас канвас в режиме измерения угла или в режиме редактирования других элементов.
- Режим измерения угла не должен случайно запускать редактирование контура или калибровки.
- После завершения угла приложение может остаться в режиме измерения следующего угла или выйти из режима; выбрать поведение в стиле существующих инструментов и сделать его предсказуемым.
- Нельзя допустить зависание инструмента в промежуточном состоянии после отмены, ошибки или переключения изображения.

Рекомендации по реализации:
- Добавить отдельную структуру для временного угла в памяти, например `AngleMeasurement` с полями `first`, `vertex`, `second`.
- В канвасе отделить angle handles от contour handles и calibration handles.
- Для узлов угла можно сделать отдельный `QGraphicsEllipseItem` с типом узла: first, vertex, second.
- Для линий можно использовать `QGraphicsLineItem`; для подписи `QGraphicsTextItem` или `QGraphicsSimpleTextItem`.
- Для расчёта угла использовать стабильную формулу через скалярное произведение и `acos`, предварительно ограничивая cos в диапазоне `[-1, 1]`.
- Сохранять стиль существующего кода для сигналов, сообщений, действий toolbar/menu и тестов.
- Если текущий канвас уже умеет сохранять временные элементы по ID изображения, использовать этот подход; если нет, добавить минимальную in-memory привязку.

Критерии приёмки:
- В интерфейсе есть действие "Угол".
- Пользователь может создать измерение угла тремя кликами на выбранном изображении.
- Во время создания отображаются понятные промежуточные точки и временные линии.
- После третьего клика на канвасе видны две стороны угла, три узла и подпись значения в градусах.
- Значение угла рассчитывается корректно по трём точкам.
- При перемещении любого узла угол и подпись пересчитываются динамически.
- Подпись расположена возле вершины и остаётся читаемой при масштабировании.
- Действие "Удалить угол" удаляет измерение только когда выбрана вершина этого угла.
- Если вершина не выбрана, удаление угла не меняет канвас и не затрагивает контур или калибровку.
- Углы не сохраняются в JSON проекта и не запускают автосохранение.
- При переключении между изображениями отображаются только углы текущего изображения в рамках текущей сессии.
- При закрытии проекта временные углы очищаются.
- Существующие сценарии контура, калибровки, расчёта свойств и экспорта продолжают работать.
- Существующие тесты проходят.
- Добавлены или обновлены тесты на:
  - создание угла тремя кликами;
  - preview-состояния после первого и второго клика;
  - корректный расчёт угла;
  - перетаскивание узлов и пересчёт подписи;
  - удаление угла по выбранной вершине;
  - запрет удаления без выбранной вершины;
  - отсутствие углов в JSON;
  - очистку или скрытие углов при переключении изображения/закрытии проекта.
