Задача: заменить жёсткую порядковую нумерацию углов в интерфейсе на редактируемое имя угла и синхронизировать это имя с подписью на канвасе.

Контекст:
- Проект MagicBorder - настольное приложение на PyQt5.
- Углы уже являются проектными измерениями изображения:
  - модель угла описана в `ProjectAngleMeasurement` в `src/magicborder/models.py`;
  - углы хранятся в `ProjectImageRecord.measurements.angles`;
  - JSON проекта содержит блок `measurements.angles`;
  - канвас работает с углами через `ImageCanvas` в `src/magicborder/canvas.py`;
  - панель "Свойства изображения" строится в `src/magicborder/main_window.py`.
- Сейчас каждый угол в панели свойств отображается как группа с жёстким названием по порядку:
  - `Угол 1`;
  - `Угол 2`;
  - `Угол 3`.
- Сейчас подпись угла на канвасе также формируется из порядкового номера:
  - `Угол 1: 90°`;
  - `Угол 2: 45°`.
- В исходной формулировке упомянута подгруппа "Узлы". В текущем интерфейсе речь должна идти о подгруппе "Углы" внутри группы "Измерения". Если в коде есть отдельная подгруппа "Узлы", не менять её без необходимости.

Область изменений:
- `src/magicborder/models.py`:
  - модель проектного измерения угла;
  - сериализация и загрузка JSON;
  - обратная совместимость со старыми проектами без имени угла.
- `src/magicborder/canvas.py`:
  - хранение и передача имени угла в canvas-модели;
  - формат подписи угла на канвасе;
  - обновление подписи при изменении имени.
- `src/magicborder/main_window.py`:
  - построение группы "Измерения" -> "Углы";
  - редактируемое поле имени угла;
  - синхронизация модели, панели свойств и канваса;
  - сохранение проекта после изменения имени.
- Тесты:
  - `tests/test_project_models.py`;
  - `tests/test_canvas.py`;
  - `tests/test_project_properties.py`.

Не входит в задачу:
- Не менять способ создания угла тремя кликами.
- Не менять расчёт значения угла в градусах.
- Не менять геометрию линий, дуги и draggable-узлов угла.
- Не менять стабильный `id` угла и не использовать его как пользовательское имя.
- Не менять смысл поля `note` / "Примечание": имя угла и примечание должны быть разными полями.
- Не менять порядок углов в коллекции без отдельной необходимости.
- Не добавлять новые типы измерений.
- Не менять UI групп контура, калибровки, цветов, локации и дополнительных сведений.

Требования к модели данных:
- Добавить в `ProjectAngleMeasurement` редактируемое пользовательское имя угла, например поле:
  - `name: str = ""`;
  - либо `label: str = ""`, если это лучше совпадает с существующими именами в проекте.
- Рекомендуемое имя поля в JSON: `name`.
- JSON одного угла должен сохранять имя рядом с текущими полями:
  ```json
  {
    "id": "angle-...",
    "name": "Контрольный угол",
    "first": {"x": 10.0, "y": 20.0},
    "vertex": {"x": 10.0, "y": 10.0},
    "second": {"x": 20.0, "y": 10.0},
    "note": ""
  }
  ```
- Старые проекты, где у углов нет поля `name`, должны открываться без ошибок.
- Для старых углов без имени нужно вычислять отображаемое имя из текущего порядка:
  - первый угол -> `Угол 1`;
  - второй угол -> `Угол 2`;
  - и так далее.
- Не заполнять `name` автоматически значением `Угол N` при загрузке старого проекта, если это приведёт к лишнему изменению JSON без действия пользователя.
- При сохранении новых или переименованных углов поле `name` должно попадать в JSON.
- Если пользователь очищает имя угла, использовать fallback-имя `Угол N` для отображения, но хранить пустое значение или нормализованное значение согласно выбранному подходу. Поведение должно быть явно закреплено тестом.

Требования к панели "Свойства изображения":
- В подгруппе "Измерения" -> "Углы" элементы коллекции больше не должны называться только по жёсткому `Угол N`, если у угла есть пользовательское имя.
- Заголовок группы конкретного угла должен показывать отображаемое имя:
  - если `name = "Контрольный угол"`, заголовок группы: `Контрольный угол`;
  - если `name` пустой, заголовок группы: `Угол N`.
- Внутри группы каждого угла добавить редактируемое поле:
  - подпись поля: `Имя`;
  - виджет: `QLineEdit`;
  - ключ свойства должен быть уникальным, например `angle:<id>:name`.
- Поле "Примечание" оставить отдельным и продолжать сохранять в `note`.
- Изменение поля "Имя" должно:
  - обновить `ProjectAngleMeasurement.name`;
  - обновить заголовок группы угла в панели свойств;
  - обновить подпись этого угла на канвасе;
  - запланировать сохранение проекта;
  - не менять геометрию угла;
  - не менять `id` угла;
  - не менять порядок углов.
- Если имя совпадает с текущим, лишний autosave не должен запускаться.
- Если у нескольких углов одинаковое имя, приложение не должно ломаться. Разрешить одинаковые имена или добавить мягкую нормализацию только если это уже принято в UI проекта. В любом случае связь с сущностью должна оставаться через `id`.

Требования к подписи на канвасе:
- Подпись угла должна использовать отображаемое имя, а не жёстко вычисленное `Угол N`.
- Формат подписи:
  - `<имя угла>: <значение>`;
  - например `Контрольный угол: 90°`;
  - для угла без пользовательского имени: `Угол 1: 90°`.
- Значение угла после двоеточия должно форматироваться как раньше:
  - округление не менять;
  - знак градуса не менять;
  - `None` / невалидное значение показывать в текущем стиле, например `-`.
- При переименовании угла подпись на канвасе должна обновляться сразу, без переключения изображения и без пересоздания проекта.
- При перемещении узлов угла:
  - значение в подписи должно пересчитываться;
  - имя должно сохраняться.
- При удалении угла:
  - оставшиеся углы с пользовательским именем должны сохранить свои имена;
  - углы без пользовательского имени должны получить актуальный fallback `Угол N` без пропусков.
- При загрузке проекта, переключении изображения, очистке углов и пересборке графики подписи должны оставаться согласованными с моделью.

Требования к API канваса:
- Расширить внутреннюю canvas-модель угла так, чтобы она знала отображаемое имя или пользовательское имя:
  - например добавить поле `name` в `AngleMeasurement`;
  - либо передавать список имён в отдельном API, если это лучше вписывается в текущую архитектуру.
- Расширить `set_angle_measurement_records` и `angle_measurement_records` так, чтобы имя не терялось при синхронизации между `MainWindow` и `ImageCanvas`.
- Сохранить обратную совместимость существующих canvas API, если они используются тестами или другим кодом:
  - `set_angle_measurements` может продолжать принимать только геометрию и создавать углы с пустым пользовательским именем;
  - старые tuple-структуры можно поддержать через нормализацию.
- Рекомендуется вынести форматирование подписи в helper, например:
  - `_angle_display_name(name: str, angle_index: int) -> str`;
  - `_format_angle_label(display_name: str, angle_degrees: float | None) -> str`.

Требования к синхронизации:
- Источником пользовательского имени должна быть проектная модель `ProjectAngleMeasurement`, а не текст QTreeWidget и не canvas label.
- При создании нового угла:
  - создать угол с пустым пользовательским именем;
  - в UI и на канвасе показать fallback `Угол N`;
  - сохранить возможность сразу переименовать его через панель свойств.
- При `_store_current_angle_measurements` не терять существующие `name` и `note`.
- При удалении угла из панели свойств или с канваса не терять имена оставшихся углов.
- При переключении изображения на канвас должны попадать имена углов выбранного изображения.
- При сохранении и повторной загрузке проекта имена углов должны восстановиться.

Требования к тестам:
- Обновить тесты модели проекта:
  - round-trip `measurements.angles` сохраняет `name`;
  - старый JSON без `name` загружается корректно;
  - `note` продолжает сохраняться отдельно от `name`.
- Обновить тесты канваса:
  - угол без имени показывает fallback `Угол 1: 90°`;
  - угол с именем показывает `Контрольный угол: 90°`;
  - после изменения геометрии значение обновляется, а имя остаётся;
  - после удаления одного угла fallback-имена оставшихся углов без пользовательского имени перенумеровываются без пропусков;
  - пользовательские имена оставшихся углов не заменяются на `Угол N`.
- Обновить UI-тесты панели свойств:
  - в группе конкретного угла есть редактируемое поле `Имя`;
  - заголовок группы использует имя угла, если оно задано;
  - изменение имени через `QLineEdit` обновляет модель;
  - изменение имени обновляет подпись на канвасе;
  - изменение имени сохраняется в JSON;
  - после повторного открытия проекта имя отображается в панели и на канвасе;
  - поле `Примечание` продолжает работать как раньше.
- Тесты не должны требовать видимого GUI-окна; использовать существующий offscreen-подход.

Критерии приёмки:
- В подгруппе "Измерения" -> "Углы" название элемента угла больше не ограничено жёсткой нумерацией `Угол N`.
- У каждого угла есть редактируемое поле `Имя`.
- Если имя задано, оно отображается:
  - в заголовке группы угла в панели свойств;
  - в подписи угла на канвасе перед значением градусов.
- Если имя не задано, интерфейс использует fallback `Угол N`.
- Переименование угла сразу обновляет canvas label.
- Имя угла сохраняется в JSON и восстанавливается при открытии проекта.
- `id`, геометрия, `note`, удаление, создание, переключение изображений и существующие сценарии измерения углов продолжают работать.
- Старые проекты без поля `name` открываются без ошибок.
- Существующие тесты проходят; добавлены или обновлены тесты для имени угла.
