Задача: расширить экспорт панели "Свойства изображения" в Excel и добавить удобный выбор свойств по группам и подгруппам.

Исходная формулировка:
"Необходимо внести изменения в механизм экспорта Свойства изображения в файл эксель:
1. Добавить элементы свойств которых раньше не было.
2. Помимо конкретных свойств в диалоге добавить выбор (либо отмена выбора) по группам и подгруппам свойств."

Контекст проекта:
- MagicBorder - настольное приложение на PyQt5.
- Панель "Свойства изображения" строится в `src/magicborder/main_window.py`.
- Экспорт свойств выбранного изображения в Excel уже реализован:
  - action/button: `export_image_properties_excel_action`, `export_image_properties_excel_button`;
  - entrypoint: `export_image_properties_excel()`;
  - диалог выбора: `_select_image_property_export_items()`;
  - общий helper выбора: `_select_checked_export_items(...)`;
  - запись файла: `_write_image_properties_excel(...)`;
  - сбор значений: `_image_property_export_values(...)`;
  - статические группы экспорта: `IMAGE_PROPERTY_GROUPS`;
  - список ключей: `IMAGE_PROPERTY_EXPORT_KEYS`;
  - подписи: `IMAGE_PROPERTY_EXPORT_LABELS`;
  - запись `.xlsx`: `write_xlsx_table(...)` из `src/magicborder/io_utils.py`.
- Сейчас Excel для свойств изображения пишется вертикально двумя колонками:
  - `Свойство`;
  - `Значение`.
- Диалог выбора сейчас показывает список свойств, сгруппированный визуальными строками, но группы не являются checkable-узлами и не позволяют одним действием выбрать или снять все дочерние свойства.
- Панель свойств изображения содержит больше данных, чем текущий экспорт. В частности, в экспорт не попадают часть свойств главного контура и динамические свойства измерений.

Главное требование:
- Экспорт "Свойства изображения в Excel" должен уметь экспортировать все содержательные свойства, которые пользователь видит в панели "Свойства изображения".
- В диалоге выбора свойств нужно добавить checkable-группы и checkable-подгруппы:
  - снятие галочки с группы снимает все её дочерние свойства;
  - установка галочки на группе выбирает все её дочерние свойства;
  - частично выбранная группа отображается в промежуточном состоянии;
  - то же поведение должно работать для вложенных подгрупп, например `Измерения` -> `Углы` -> `Угол 1`.
- В Excel должны попадать только выбранные конечные свойства, а не заголовки групп.

Область изменений:
- `src/magicborder/main_window.py`:
  - расширить список/дерево экспортируемых свойств изображения;
  - добавить поддержку иерархического выбора свойств в диалоге;
  - сохранить существующий сценарий экспорта списка изображений проекта;
  - сохранить вертикальный формат Excel для свойств изображения;
  - добавить значения экспорта для новых ключей.
- `tests/test_project_properties.py`:
  - добавить тесты на новые экспортируемые свойства;
  - добавить тесты на выбор/снятие выбора по группам и подгруппам;
  - обновить существующие тесты, если статический список ключей расширится.

Не входит в задачу:
- Не менять формат `.xlsx`: оставить лист `Свойства` и колонки `Свойство`, `Значение`.
- Не менять экспорт списка изображений проекта, кроме аккуратного переиспользования общего диалога, если это удобно.
- Не менять JSON-структуру проекта.
- Не сохранять временную canvas-видимость контура, углов или отрезков в проектный JSON.
- Не добавлять зависимость `openpyxl` или другие Excel-библиотеки: использовать существующий `write_xlsx_table(...)`.
- Не экспортировать управляющие кнопки из панели свойств, например строки `Управление` с кнопкой удаления.
- Не экспортировать placeholder-строки `Нет углов` и `Нет отрезков` как обычные свойства.

Требования к подписям строк Excel:
- Для уже существующих статических свойств сохранить текущие подписи, чтобы не ломать существующие ожидания:
  - например `file_name` продолжает экспортироваться как `Файл`;
  - `diagnosis` как `Диагноз`;
  - `status` как `Статус`.
- Для динамических свойств измерений подпись в колонке `Свойство` должна быть однозначной.
- Рекомендуемый формат для измерений:
  - `Угол 1 / ID`;
  - `Угол 1 / Значение`;
  - `Контрольный угол / Примечание`;
  - `Отрезок 1 / Длина`;
  - `Контрольный отрезок / Подпись первой точки`.
- Если в проекте несколько измерений с одинаковыми пользовательскими именами, всё равно использовать их display-name как в панели свойств; ключи остаются уникальными за счёт `id`.

Требования к диалогу выбора:
- Для свойств изображения заменить плоский `QListWidget` на иерархический UI, например `QTreeWidget`.
- Конечные свойства должны быть checkable.
- Группы и подгруппы должны быть checkable.
- Все конечные свойства должны быть выбраны по умолчанию.
- Все группы должны быть checked по умолчанию, если все их дочерние свойства checked.
- Если пользователь снимает галочку с группы, все дочерние группы и свойства становятся unchecked.
- Если пользователь ставит галочку на группе, все дочерние группы и свойства становятся checked.
- Если пользователь меняет дочерние свойства вручную, состояние родительских групп должно пересчитываться:
  - checked, если выбраны все дочерние свойства;
  - unchecked, если не выбрано ни одно дочернее свойство;
  - partially checked, если выбрана только часть.
- Кнопка `OK` должна принимать диалог только если выбран хотя бы один конечный property-key.
- Кнопка `Cancel` должна возвращать `None` и не открывать `QFileDialog.getSaveFileName`.
- Порядок выбранных ключей должен соответствовать визуальному порядку дерева сверху вниз.
- Группы не должны попадать в возвращаемый список selected keys.
- Для проекта (`_select_project_export_columns`) можно оставить плоский список или перевести на общий helper без вложенных групп, но текущие тесты проекта должны продолжать проходить.

Рекомендации по реализации:
- Не пытаться расширять старую структуру `list[tuple[str, str]]` до сложных вложений через неявные sentinel-значения.
- Лучше ввести явную небольшую структуру для дерева экспорта, например dataclass или typed dict:
  - group node: title + children;
  - leaf node: key + label + optional export_label.
- Допустимо оставить `IMAGE_PROPERTY_GROUPS` как статическое описание базовых групп и добавить helper, который для текущего record добавляет динамические `Измерения`.
- Возможные helper-методы:
  - `_image_property_export_groups(record: ProjectImageRecord | None)`;
  - `_image_property_export_labels(record: ProjectImageRecord | None) -> dict[str, str]`;
  - `_image_property_export_leaf_keys(record: ProjectImageRecord | None) -> list[str]`;
  - `_measurement_property_export_groups(record: ProjectImageRecord)`.
- `_select_image_property_export_items()` должен строить дерево на основе текущего selected record.
- Если selected record отсутствует, использовать только статические группы.
- `_write_image_properties_excel(...)` должен брать labels и values для того же record, который экспортируется.
- Не полагаться на глобальный `IMAGE_PROPERTY_EXPORT_LABELS` для динамических ключей измерений, потому что ключи зависят от `id`.
- Старые constants можно сохранить для обратной совместимости тестов:
  - `IMAGE_PROPERTY_EXPORT_KEYS` может оставаться списком статических ключей;
  - если добавляется `contour_visible`, он должен попасть в этот список в правильном месте.
- Для рекурсивного обновления check-state в `QTreeWidget` использовать `QSignalBlocker` или явный флаг, чтобы изменение родителя не запускало бесконечную цепочку сигналов.
- Если используется `Qt.PartiallyChecked`, учитывать его только на группах; конечные свойства должны быть только checked/unchecked.

Поведение при экспорте:
- `export_image_properties_excel()` по-прежнему должен:
  - проверить наличие проекта;
  - проверить выбранное изображение;
  - сохранить текущую аннотацию через `_save_current_project_annotation()`;
  - обновить панель через `_update_project_properties()`;
  - открыть диалог выбора свойств;
  - при `None` из диалога завершиться без file dialog;
  - при пустом списке показать warning `Нет выбранных свойств`;
  - запросить путь сохранения;
  - записать `.xlsx`;
  - показать status-bar сообщение об успехе.
- `_write_image_properties_excel(...)` должен игнорировать неизвестные ключи безопасно или писать для них пустое значение, но лучше не генерировать неизвестные ключи в диалоге.
- Порядок строк в Excel должен соответствовать порядку selected keys.
- Если пользователь выбрал всю группу `Измерения`, строки углов должны идти перед строками отрезков, как в панели.
- Если у изображения нет углов или отрезков, группа `Измерения` может отсутствовать в диалоге или содержать пустые disabled-подгруппы, но не должна добавлять экспортируемые строки `Нет углов` / `Нет отрезков`.

Сохранение и side effects:
- Экспорт не должен менять проектную модель.
- Экспорт не должен запускать autosave только из-за выбора свойств.
- Экспорт не должен менять видимость контура, углов или отрезков.
- Экспорт не должен менять выделение на canvas.
- Если временная видимость угла/отрезка была выключена, экспортировать её как `Нет`, но не сохранять это в JSON.

- Пользователь может выбрать отдельные свойства изображения, целую группу или вложенную подгруппу.
- Выбор/снятие выбора группы корректно меняет дочерние checkbox-элементы.
- Экспорт включает все содержательные строки панели "Свойства изображения", включая:
  - `Показывать контур`;
  - свойства каждого угла;
  - свойства каждого отрезка.
- Excel остаётся читаемым: динамические строки измерений имеют однозначные подписи.
- Экспорт не меняет проект, canvas и JSON.
- Проходят тесты `tests/test_project_properties.py`.
