Задача: синхронизировать визуальную подсветку измерений с работой пользователя на canvas.

Исходная формулировка:
"Необходимо внести изменения в поведение интерфейса:
1. Поведение при работе с элементами измерений: если мы работаем с конкретным измерением (уже созданным) то элемент (итем) считается выделенным, поэтому необходимо соответсвующие его линии делать более толстыми как в случае нажатия в окне свойств изображенияю."

Контекст проекта:
- MagicBorder - настольное приложение на PyQt5.
- Canvas реализован в `src/magicborder/canvas.py`, класс `ImageCanvas`.
- Основное окно реализовано в `src/magicborder/main_window.py`.
- Панель "Свойства изображения" строится через `PropertyBrowser` в `src/magicborder/property_browser.py`.
- В предыдущей задаче уже добавлена визуальная подсветка измерений при клике в панели "Свойства изображения":
  - `ImageCanvas.highlight_angle_measurement(...)`;
  - `ImageCanvas.highlight_segment_measurement(...)`;
  - `ImageCanvas.clear_measurement_highlight()`;
  - `ImageCanvas.highlighted_angle_id()`;
  - `ImageCanvas.highlighted_segment_id()`;
  - утолщение линий/дуги/handles через highlighted-состояние.
- Сейчас подсветка включается при клике по строкам свойства угла или отрезка, но не должна ограничиваться только панелью свойств.
- Если пользователь работает с уже созданным измерением прямо на canvas, это измерение тоже должно считаться активным/выделенным и получать ту же визуальную подсветку.

Главное требование:
- При работе пользователя с конкретным уже созданным углом или отрезком на canvas соответствующее измерение должно автоматически подсвечиваться так же, как при клике по этому измерению в панели "Свойства изображения".
- Под "работой с измерением" понимать:
  - выбор handle существующего угла;
  - выбор handle существующего отрезка;
  - перетаскивание handle существующего угла;
  - перетаскивание handle существующего отрезка.
- В подсвеченном состоянии линии измерения должны быть толще обычных.
- Для угла должны утолщаться:
  - оба луча;
  - дуга угла;
  - handles угла визуально усиливаются тем же способом, который уже используется для highlighted-состояния.
- Для отрезка должны утолщаться:
  - линия отрезка;
  - endpoint handles визуально усиливаются тем же способом, который уже используется для highlighted-состояния.

Область изменений:
- `src/magicborder/canvas.py`:
  - добавить или обновить синхронизацию highlighted-состояния при выборе handles измерений;
  - добавить или обновить синхронизацию highlighted-состояния при перемещении handles измерений;
  - сохранить существующую selection/delete-семантику canvas.
- `src/magicborder/main_window.py`:
  - при необходимости обновить реакцию на `angle_state_changed` и `segment_state_changed`;
  - не дублировать в `MainWindow` логику определения выбранных handles, если её можно держать в `ImageCanvas`.
- `tests/test_canvas.py`:
  - добавить тесты на highlighted-состояние при выборе и перемещении handles.
- `tests/test_project_properties.py`:
  - добавить или обновить интеграционные тесты, если нужно проверить состояние actions или совместимость с кликами в панели свойств.

Не входит в задачу:
- Не менять формат проектного JSON.
- Не сохранять highlighted-состояние в проект.
- Не сохранять временную видимость измерений в проект.
- Не менять формат Excel-экспорта.
- Не менять порядок или состав строк панели "Свойства изображения".
- Не добавлять новые команды toolbar.
- Не добавлять новые SVG-иконки.
- Не менять цвета обычных измерений без необходимости.
- Не делать линии всегда толстыми: утолщение должно быть только для активного/выделенного измерения.
- Не включать автоматически видимость скрытого измерения только из-за highlighted-состояния.

Требования к поведению выбора углов:
- Если пользователь выбирает любой handle угла на canvas, весь этот угол становится highlighted.
- Это должно работать для всех трёх точек угла:
  - первая точка луча;
  - вершина;
  - вторая точка луча.
- Если пользователь перетаскивает любой handle угла, угол должен оставаться highlighted во время и после перемещения.
- Выбор вершины угла должен сохранить текущую delete-семантику:
  - `has_selected_angle_vertex()` возвращает `True`;
  - action удаления угла включается как раньше.
- Выбор не-вершинной точки угла должен подсвечивать угол, но не должен превращаться в выбор вершины:
  - `has_selected_angle_vertex()` остаётся `False`;
  - action удаления угла не должен включаться только из-за выбора точки луча.
- Если выбран другой угол, подсветка должна перейти на него.
- Если все handles углов и отрезков сняты с выбора из-за клика по пустому месту canvas или выбора другого объекта, подсветку измерения нужно очистить, если нет другого активного источника подсветки.

Требования к поведению выбора отрезков:
- Если пользователь выбирает любой endpoint handle отрезка на canvas, весь отрезок становится highlighted.
- Это должно работать для обеих точек отрезка:
  - первая точка;
  - вторая точка.
- Если пользователь перетаскивает любой endpoint handle отрезка, отрезок должен оставаться highlighted во время и после перемещения.
- Выбор endpoint отрезка должен сохранить текущую delete-семантику:
  - `has_selected_segment_endpoint()` возвращает `True`;
  - action удаления отрезка включается как раньше.
- Если выбран другой отрезок, подсветка должна перейти на него.
- Если выбран handle отрезка после highlighted-угла, подсветка угла должна сброситься.
- Если выбран handle угла после highlighted-отрезка, подсветка отрезка должна сброситься.

Совместимость с подсветкой из панели свойств:
- Клик по углу или отрезку в панели "Свойства изображения" должен продолжать работать как раньше.
- Canvas-selection и property-panel-click должны использовать один общий механизм highlighted-состояния.
- Одновременно highlighted может быть максимум один элемент:
  - либо один угол;
  - либо один отрезок.
- Если сначала кликнуть измерение в панели свойств, а затем выбрать другое измерение на canvas, подсветка должна перейти на измерение с canvas.
- Если сначала выбрать измерение на canvas, а затем кликнуть другое измерение в панели свойств, подсветка должна перейти на измерение из панели свойств.
- Подсветка не должна выбирать строку в `PropertyBrowser`, если в текущем UI нет такого selection-поведения.
- Не нужно автоматически раскрывать группу измерения в панели свойств при выборе handle на canvas, если это не реализовано сейчас.

Рекомендации по реализации:
- Не создавать второй независимый механизм подсветки.
- Использовать уже существующие методы:
  - `highlight_angle_measurement(angle_id)`;
  - `highlight_segment_measurement(segment_id)`;
  - `clear_measurement_highlight()`.
- В `ImageCanvas` удобно добавить helper-методы, например:
  - `_selected_angle_handle_index() -> int | None`;
  - `_selected_segment_handle_index() -> int | None`;
  - `_sync_measurement_highlight_from_selection()`;
  - `_angle_id_by_index(index)`;
  - `_segment_id_by_index(index)`.
- В `AngleHandleItem.itemChange(...)` уже вызывается `self.canvas.angle_selection_changed()` при `ItemSelectedHasChanged`.
- В `SegmentHandleItem.itemChange(...)` уже вызывается `self.canvas.segment_selection_changed()` при `ItemSelectedHasChanged`.
- Можно обновить:
  - `angle_selection_changed()`;
  - `segment_selection_changed()`;
  чтобы они синхронизировали highlighted-состояние с текущим выбранным handle.
- В `angle_handle_moved(...)` и `segment_handle_moved(...)` можно явно подсвечивать измерение, которое пользователь перемещает.
- Если выделены handles нескольких измерений одновременно, выбрать один предсказуемый приоритет:
  - последнее событие выбора/перемещения имеет приоритет;
  - или сначала проверять выбранный сегмент/угол по текущему событию.
- Не полагаться только на `selected_angle_id()`, если он сейчас возвращает id только при выбранной вершине угла.
- Для угла может понадобиться отдельный helper, который возвращает id угла по любому выбранному `AngleHandleItem`, а не только по вершине.
- При удалении измерения подсветка удалённого id должна сбрасываться, если это ещё не сделано.
- При пересборке графики измерений highlighted-состояние должно либо восстановиться для существующего id, либо очиститься, если id больше нет.

Side effects:
- Работа с highlighted-состоянием не должна запускать autosave.
- Работа с highlighted-состоянием не должна менять модель проекта.
- Работа с highlighted-состоянием не должна менять временную видимость элементов.
- Работа с highlighted-состоянием не должна менять координаты измерений, кроме обычного перемещения handle пользователем.
- Перемещение handle по-прежнему должно обновлять координаты измерения и сохраняться как раньше.

Проверки вручную:
- Открыть изображение с уже созданным углом и отрезком.
- Кликнуть первую точку угла:
  - весь угол визуально утолщается;
  - кнопка удаления угла не включается, если это не вершина.
- Кликнуть вершину угла:
  - угол визуально утолщается;
  - кнопка удаления угла включается как раньше.
- Перетащить точку угла:
  - угол остаётся утолщённым во время работы.
- Кликнуть endpoint отрезка:
  - весь отрезок визуально утолщается;
  - кнопка удаления отрезка включается как раньше.
- Перетащить endpoint отрезка:
  - отрезок остаётся утолщённым во время работы.
- Кликнуть другой угол или отрезок:
  - предыдущая подсветка сбрасывается;
  - новый элемент становится подсвеченным.
- Кликнуть обычное свойство изображения или пустое место:
  - подсветка очищается, если активного измерения больше нет.

Критерии готовности:
- Работа с уже созданным углом на canvas включает ту же подсветку, что и клик по этому углу в панели свойств.
- Работа с уже созданным отрезком на canvas включает ту же подсветку, что и клик по этому отрезку в панели свойств.
- Для углов подсветка работает при выборе любой из трёх точек.
- Для отрезков подсветка работает при выборе любой из двух точек.
- Утолщение линий не ломает delete-семантику.
- Highlighted-состояние не сохраняется в проект и не запускает autosave.
- Проходят тесты:
  - `env PYTHONPATH=src uv run pytest tests/test_canvas.py tests/test_project_properties.py`;
  - желательно также `env PYTHONPATH=src uv run pytest`.
