Задача: добавить у измерений типа "Отрезки" редактируемое имя и примечание, сохранять их в JSON проекта и синхронизировать имя с подписью отрезка на канвасе.

Контекст:
- Проект MagicBorder - настольное приложение на PyQt5.
- Измерения изображения хранятся в проектной модели в блоке `measurements`.
- Отрезки уже добавлены как проектные измерения:
  - модель отрезка описана в `ProjectSegmentMeasurement` в `src/magicborder/models.py`;
  - отрезки хранятся в `ProjectImageRecord.measurements.segments`;
  - JSON проекта содержит блок `measurements.segments`;
  - канвас работает с отрезками через `ImageCanvas` в `src/magicborder/canvas.py`;
  - панель "Свойства изображения" строится в `src/magicborder/main_window.py`;
  - в группе "Измерения" уже есть подгруппа "Отрезки".
- Сейчас у отрезка есть:
  - стабильный `id`;
  - точки `start` и `end`;
  - подписи точек `start_label` и `end_label`;
  - вычисляемая длина в пикселях и, при наличии калибровки, в миллиметрах.
- Сейчас элементы подгруппы "Отрезки" могут отображаться как жёсткая порядковая нумерация:
  - `Отрезок 1`;
  - `Отрезок 2`;
  - `Отрезок 3`.
- Нужно сделать имя отрезка пользовательским полем, как у углов, и добавить отдельное поле "Примечание".

Область изменений:
- `src/magicborder/models.py`:
  - модель `ProjectSegmentMeasurement`;
  - сериализация и загрузка JSON;
  - обратная совместимость со старыми проектами без `name` и `note`.
- `src/magicborder/canvas.py`:
  - хранение и передача имени отрезка в canvas-модели;
  - отображение имени на канвасе над подписью длины;
  - обновление подписи при переименовании и изменении геометрии.
- `src/magicborder/main_window.py`:
  - построение подгруппы "Измерения" -> "Отрезки";
  - редактируемые поля "Имя" и "Примечание";
  - синхронизация model <-> properties panel <-> canvas;
  - сохранение проекта после изменения имени или примечания.
- Тесты:
  - `tests/test_project_models.py`;
  - `tests/test_canvas.py`;
  - `tests/test_project_properties.py`.

Не входит в задачу:
- Не менять способ создания отрезка двумя кликами.
- Не менять preview отрезка.
- Не менять геометрию линии, endpoint-узлов и drag-поведение.
- Не менять расчёт длины в пикселях и миллиметрах.
- Не менять калибровку и формат хранения калибровки.
- Не менять `id` отрезка и не использовать его как пользовательское имя.
- Не смешивать имя отрезка, подписи точек и примечание:
  - `name` - имя всего отрезка;
  - `start_label` - подпись первой точки;
  - `end_label` - подпись второй точки;
  - `note` - текстовое примечание.
- Не менять порядок отрезков без отдельной необходимости.
- Не менять поведение углов, главного контура, калибровки, экспорта и других групп свойств.

Требования к модели данных:
- Добавить в `ProjectSegmentMeasurement` редактируемое имя отрезка:
  - рекомендуемое поле: `name: str = ""`.
- Добавить отдельное примечание:
  - рекомендуемое поле: `note: str = ""`.
- Рекомендуемая JSON-структура одного отрезка:
  ```json
  {
    "id": "segment-...",
    "name": "Контрольный отрезок",
    "start": {"x": 10.0, "y": 20.0},
    "end": {"x": 80.0, "y": 20.0},
    "start_label": "A",
    "end_label": "B",
    "note": "измерить повторно"
  }
  ```
- Старые проекты, где у отрезков нет `name` или `note`, должны открываться без ошибок.
- Для старых отрезков без имени нужно вычислять отображаемое имя из текущего порядка:
  - первый отрезок -> `Отрезок 1`;
  - второй отрезок -> `Отрезок 2`;
  - и так далее.
- Не заполнять `name` автоматически значением `Отрезок N` при загрузке старого проекта, если это приведёт к лишнему изменению JSON без действия пользователя.
- Если пользователь очищает имя, хранить пустое значение и использовать fallback `Отрезок N` только для отображения.
- `note` должен сохраняться отдельно от `name`, `start_label` и `end_label`.
- `ProjectImageMeasurements.to_dict()` должен продолжать сохранять:
  - `angles`;
  - `segments`;
  - будущие неизвестные группы из `extra_groups`.
- При round-trip проекта неизвестные будущие ключи в `measurements` не должны теряться.

Требования к панели "Свойства изображения":
- В подгруппе "Измерения" -> "Отрезки" заголовок группы конкретного отрезка должен использовать отображаемое имя:
  - если `name = "Контрольный отрезок"`, заголовок группы: `Контрольный отрезок`;
  - если `name` пустой, заголовок группы: `Отрезок N`.
- Внутри группы каждого отрезка добавить редактируемое поле:
  - подпись поля: `Имя`;
  - виджет: `QLineEdit`;
  - ключ свойства должен быть уникальным, например `segment:<id>:name`.
- Внутри группы каждого отрезка добавить редактируемое поле:
  - подпись поля: `Примечание`;
  - виджет: `QLineEdit` или другой уже принятый в проекте текстовый виджет;
  - ключ свойства должен быть уникальным, например `segment:<id>:note`.
- Уже существующие поля оставить:
  - `ID`;
  - `Длина`;
  - `Первая точка`;
  - `Вторая точка`;
  - `Подпись первой точки`;
  - `Подпись второй точки`;
  - `Удалить`.
- Редактирование поля "Имя" должно:
  - обновить `ProjectSegmentMeasurement.name`;
  - обновить заголовок группы отрезка в панели свойств;
  - обновить подпись отрезка на канвасе;
  - запланировать сохранение проекта;
  - не менять координаты, `id`, подписи точек и порядок отрезков.
- Редактирование поля "Примечание" должно:
  - обновить `ProjectSegmentMeasurement.note`;
  - запланировать сохранение проекта;
  - не менять canvas label, если примечание не отображается на канвасе;
  - не менять координаты, `id`, имя, подписи точек и порядок отрезков.
- Если введённое имя или примечание совпадает с текущим значением, лишний autosave не должен запускаться.
- Если у нескольких отрезков одинаковое имя, приложение не должно ломаться. Связь с сущностью должна оставаться через `id`.

Требования к подписи на канвасе:
- На канвасе у завершённого отрезка должно отображаться имя отрезка над подписью длины.
- Формат рекомендуется сделать двухстрочным:
  - первая строка: отображаемое имя отрезка;
  - вторая строка: длина отрезка.
- Примеры:
  - `Контрольный отрезок`
    `120 px / 10 мм`;
  - `Отрезок 1`
    `120 px`.
- Если технически проще использовать один `QGraphicsTextItem`, допустим текст с переводом строки:
  - `Контрольный отрезок\n120 px / 10 мм`.
- Если имя пустое, использовать fallback `Отрезок N`.
- Формат длины не менять:
  - пиксели показывать как раньше;
  - миллиметры показывать как раньше при наличии калибровки;
  - округление оставить прежним;
  - длину в JSON не сохранять.
- При переименовании отрезка подпись на канвасе должна обновляться сразу, без переключения изображения и без перезагрузки проекта.
- При перемещении endpoint-узлов:
  - длина должна пересчитываться;
  - имя должно сохраняться;
  - подпись на канвасе должна оставаться согласованной.
- При изменении калибровки:
  - длина должна пересчитываться;
  - имя должно сохраняться.
- При удалении отрезка:
  - оставшиеся отрезки с пользовательским именем должны сохранить свои имена;
  - отрезки без пользовательского имени должны получить актуальный fallback `Отрезок N` без пропусков.
- Примечание на канвасе не отображать, если в текущем UI проекта нет отдельного принятого паттерна для отображения примечаний.

Требования к API канваса:
- Расширить внутреннюю canvas-модель отрезка, например `SegmentMeasurement`, полем:
  - `name: str = ""`.
- `note` можно не хранить на канвасе, если он не нужен для отображения и операций канваса.
- Расширить `set_segment_measurement_records` и `segment_measurement_records` так, чтобы `name` не терялось при синхронизации между `MainWindow` и `ImageCanvas`.
- Сохранить обратную совместимость существующих canvas API:
  - `set_segment_measurements` может продолжать принимать только геометрию и создавать отрезки с пустым пользовательским именем;
  - старые record-структуры без `name` должны нормализоваться без падения.
- Рекомендуется вынести форматирование в helpers, например:
  - `_segment_display_name(name: str, segment_index: int) -> str`;
  - `_format_segment_length_label(...) -> str`;
  - `_format_segment_label(display_name: str, length_text: str) -> str`.

Требования к синхронизации:
- Источником истины для `name` и `note` должна быть проектная модель `ProjectSegmentMeasurement`.
- При создании нового отрезка:
  - создать отрезок с пустым `name`;
  - создать отрезок с пустым `note`;
  - в UI и на канвасе показать fallback `Отрезок N`;
  - сохранить возможность сразу переименовать его через панель свойств.
- При `_store_current_segment_measurements` не терять существующие:
  - `name`;
  - `note`;
  - `start_label`;
  - `end_label`.
- При переключении изображений на канвас должны попадать имена отрезков выбранного изображения.
- При сохранении и повторной загрузке проекта имена и примечания отрезков должны восстановиться.
- При удалении отрезка из панели свойств или с канваса не терять имена и примечания оставшихся отрезков.
- Редактирование имени, примечания и подписей точек не должно менять порядок отрезков.

- Примечание сохраняется в JSON и восстанавливается при открытии проекта.

- `id`, координаты, подписи точек, расчёт длины, удаление, создание, переключение изображений и autosave продолжают работать.

- Существующие тесты проходят; добавлены или обновлены тесты для имени и примечания отрезка.
