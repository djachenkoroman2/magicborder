Задача: добавить настройку цвета подписей для измерений углов и отрезков, отображать её в свойствах сразу после настройки `Цвет линии` и сохранять в JSON проекта.

Исходная формулировка:
"В окне свойств изображения для измерений углов и отрезков необходимо добавить по аналогии с цветом линии настройку цвета подписей
Эти настройки также необходимо хранить в json проекта
В окне свойств эту настройку разместить сразу после настройки "Цвет линии""

Контекст проекта:
- MagicBorder - настольное приложение на PyQt5.
- В проекте уже есть измерения:
  - углы;
  - отрезки.
- Измерения хранятся в JSON проекта в блоке `measurements`.
- Модели измерений находятся в `src/magicborder/models.py`:
  - `ProjectAngleMeasurement`;
  - `ProjectSegmentMeasurement`;
  - `ProjectImageMeasurements`.
- Canvas-логика измерений находится в `src/magicborder/canvas.py`:
  - `AngleMeasurement`;
  - `SegmentMeasurement`;
  - `AngleGraphics`;
  - `SegmentGraphics`.
- Панель "Свойства изображения" строится в `src/magicborder/main_window.py`.
- Для углов и отрезков уже есть настройка `Цвет линии`, которая:
  - отображается в свойствах измерения;
  - открывает диалог выбора цвета;
  - обновляет линию на канвасе;
  - сохраняется в JSON проекта.
- Нужно добавить аналогичную настройку для цвета подписей.

Главное требование:
- У каждого измерения угла и отрезка должен быть отдельный настраиваемый цвет подписей.
- Цвет подписей должен:
  - отображаться в панели "Свойства изображения";
  - редактироваться через такой же UX, как `Цвет линии`;
  - сразу применяться к подписи на canvas;
  - сохраняться в JSON проекта;
  - восстанавливаться при повторном открытии проекта.
- Новое поле в свойствах должно находиться сразу после поля `Цвет линии` внутри группы конкретного угла или отрезка.

Область изменений:
- `src/magicborder/models.py`:
  - добавить поле цвета подписей в `ProjectAngleMeasurement`;
  - добавить поле цвета подписей в `ProjectSegmentMeasurement`;
  - обновить сериализацию и загрузку JSON;
  - сохранить обратную совместимость со старыми проектами.
- `src/magicborder/canvas.py`:
  - добавить хранение цвета подписей в canvas-модели угла;
  - добавить хранение цвета подписей в canvas-модели отрезка;
  - применять цвет к соответствующим `QGraphicsTextItem`;
  - обновлять цвет без перестроения всего изображения, если это возможно.
- `src/magicborder/main_window.py`:
  - добавить кнопки/поля выбора цвета подписей в свойства углов и отрезков;
  - разместить их сразу после `Цвет линии`;
  - синхронизировать model <-> properties panel <-> canvas;
  - сохранить проект после изменения цвета.
- Тесты:
  - `tests/test_project_models.py`;
  - `tests/test_canvas.py`;
  - `tests/test_project_properties.py`.

Требования к модели данных:
- Добавить поле цвета подписей для угла:
  - рекомендуемое имя: `label_color: str = ANGLE_LABEL_COLOR`;
  - если константы ещё нет, добавить понятную константу рядом с `ANGLE_LINE_COLOR`.
- Добавить поле цвета подписей для отрезка:
  - рекомендуемое имя: `label_color: str = SEGMENT_LABEL_COLOR`;
  - если константы ещё нет, добавить понятную константу рядом с `SEGMENT_LINE_COLOR`.
- Значения цвета нормализовать через существующий механизм `normalize_line_color(...)` или через новый общий helper, если название `line_color` становится семантически неудобным.
- При некорректном цвете в JSON использовать безопасный цвет по умолчанию, не падать.
- Старые проекты без `label_color` должны открываться без ошибок.
- При сохранении нового проекта `label_color` должен попадать в JSON измерений.
- Если в проекте уже используется политика не сохранять default-значения для некоторых полей, выбрать вариант, согласованный с существующим `line_color`.
- Не менять имена существующих JSON-полей:
  - `line_color`;
  - `name`;
  - `note`;
  - `start_label`;
  - `end_label`;
  - `assessment`.
- Не менять формат координат и `id` измерений.

Рекомендуемый JSON для угла:
```json
{
  "id": "angle-...",
  "name": "Угол OIV 601",
  "first": {"x": 10.0, "y": 20.0},
  "vertex": {"x": 30.0, "y": 40.0},
  "second": {"x": 60.0, "y": 20.0},
  "line_color": "#22c55e",
  "label_color": "#166534",
  "note": ""
}
```

Рекомендуемый JSON для отрезка:
```json
{
  "id": "segment-...",
  "name": "Длина листа",
  "start": {"x": 10.0, "y": 20.0},
  "end": {"x": 80.0, "y": 20.0},
  "line_color": "#f97316",
  "label_color": "#9a3412",
  "start_label": "A",
  "end_label": "B",
  "note": ""
}
```

Требования к цветам по умолчанию:
- Цвет подписей угла по умолчанию должен соответствовать текущему визуальному поведению canvas.
  - Сейчас подпись угла может использовать фиксированный зелёный цвет вроде `#166534`.
- Цвет подписей отрезка по умолчанию должен соответствовать текущему визуальному поведению canvas.
  - Сейчас основная подпись длины отрезка может использовать фиксированный оранжево-коричневый цвет вроде `#9a3412`.
  - Подписи конечных точек могут использовать близкий цвет вроде `#c2410c`.
- Если для отрезка сейчас разные цвета у подписи длины и подписей точек, выбрать одно из двух решений:
  - один `label_color` применяется ко всем текстовым подписям отрезка;
  - или один `label_color` применяется к основной подписи отрезка/длины, а endpoint-подписи остаются в текущем стиле.
- Предпочтительный вариант для простоты UX: один `label_color` для всех текстовых подписей конкретного отрезка.
- В любом случае явно зафиксировать выбранное поведение в коде и тестах.

Требования к canvas:
- Для угла цвет подписей должен применяться к текстовой подписи угла:
  - имя угла;
  - числовое значение угла;
  - итоговый `QGraphicsTextItem`, который показывает label угла.
- Для отрезка цвет подписей должен применяться к текстовым элементам отрезка:
  - подпись длины/имени отрезка;
  - подпись первой точки, если она отображается;
  - подпись второй точки, если она отображается;
  - либо только к основной подписи, если такое решение выбрано и явно отражено в тестах.
- Изменение цвета подписей должно обновляться сразу:
  - без переключения изображения;
  - без перезагрузки проекта;
  - без изменения геометрии измерения.
- При перемещении точек угла или отрезка выбранный цвет подписей должен сохраняться.
- При изменении калибровки выбранный цвет подписей отрезка должен сохраняться.
- При скрытии и повторном показе измерения цвет подписей должен сохраняться.
- При перестроении canvas-графики цвет подписей не должен сбрасываться на default.
- При удалении одного измерения цвета подписей остальных измерений не должны меняться.

Требования к canvas API:
- Добавить методы для углов:
  - получить цвет подписей угла, например `angle_measurement_label_color(angle_id)`;
  - задать цвет подписей угла, например `set_angle_measurement_label_color(angle_id, color_name)`.
- Добавить методы для отрезков:
  - получить цвет подписей отрезка, например `segment_measurement_label_color(segment_id)`;
  - задать цвет подписей отрезка, например `set_segment_measurement_label_color(segment_id, color_name)`.
- Методы установки должны:
  - нормализовать цвет;
  - возвращать `False`, если измерение не найдено или цвет не изменился;
  - возвращать `True`, если цвет изменён;
  - обновлять соответствующие `QGraphicsTextItem`.
- Расширить canvas record API:
  - `set_angle_measurement_records(...)`;
  - `angle_measurement_records(...)`;
  - `set_segment_measurement_records(...)`;
  - `segment_measurement_records(...)`.
- Сохранить обратную совместимость старых tuple-форматов canvas API, если они используются в тестах или существующем коде.

Требования к панели "Свойства изображения":
- В группе каждого угла добавить поле:
  - подпись: `Цвет подписей`;
  - тип виджета: такая же кнопка/цветовой swatch, как для `Цвет линии`;
  - расположение: сразу после `Цвет линии`.
- В группе каждого отрезка добавить поле:
  - подпись: `Цвет подписей`;
  - тип виджета: такая же кнопка/цветовой swatch, как для `Цвет линии`;
  - расположение: сразу после `Цвет линии`.
- Ключи свойств должны быть уникальными:
  - например `angle:<id>:label_color`;
  - например `segment:<id>:label_color`.
- Цветовая кнопка должна:
  - показывать текущий цвет;
  - иметь tooltip или status-tip в стиле существующих кнопок цвета;
  - открывать стандартный диалог выбора цвета;
  - не менять цвет при отмене диалога.
- После выбора цвета:
  - обновить проектную модель;
  - обновить canvas;
  - обновить кнопку цвета;
  - запланировать сохранение проекта;
  - не менять геометрию, имя, примечание, оценку и цвет линии.
- Если выбран тот же цвет, лишний autosave не должен запускаться.

Требования к синхронизации:
- Источник истины для `label_color` - проектная модель измерения.
- При создании нового угла или отрезка:
  - использовать default `label_color`;
  - показать этот цвет в свойствах;
  - передать этот цвет в canvas.
- При `_store_current_angle_measurements` не терять:
  - `name`;
  - `note`;
  - `line_color`;
  - `label_color`;
  - `assessment`.
- При `_store_current_segment_measurements` не терять:
  - `name`;
  - `note`;
  - `line_color`;
  - `label_color`;
  - `start_label`;
  - `end_label`;
  - `assessment`.
- При переключении изображений выбранные цвета подписей должны загружаться на canvas вместе с измерениями выбранного изображения.
- При сохранении и повторном открытии проекта цвета подписей должны восстановиться.
- При round-trip JSON неизвестные будущие поля в `measurements` не должны теряться, если такая совместимость уже поддерживается.

Не входит в задачу:
- Не менять цвет линии.
- Не менять цвет главного контура.
- Не добавлять настройку цвета подписей для калибровочного отрезка, если это не требуется явно.
- Не менять текст подписей, формат угла, формат длины и округление.
- Не менять алгоритм расчёта углов, длин и калибровки.
- Не менять порядок измерений.
- Не менять id измерений.
- Не менять экспорт свойств, если он не зависит напрямую от списка отображаемых свойств.
- Не добавлять новые зависимости.
- Не переделывать UI выбора цвета, если существующий color button уже подходит.

Требования к тестам модели:
- `ProjectAngleMeasurement` сохраняет `label_color` в JSON и восстанавливает его при загрузке.
- `ProjectSegmentMeasurement` сохраняет `label_color` в JSON и восстанавливает его при загрузке.
- Старый JSON угла без `label_color` загружается с default-цветом подписей.
- Старый JSON отрезка без `label_color` загружается с default-цветом подписей.
- Некорректный цвет `label_color` в JSON нормализуется к default-цвету.
- `line_color` и `label_color` хранятся независимо друг от друга.

Требования к тестам canvas:
- Угол с заданным `label_color` отображает подпись этим цветом.
- Изменение `set_angle_measurement_label_color(...)` сразу меняет цвет подписи угла.
- Отрезок с заданным `label_color` отображает подпись этим цветом.
- Изменение `set_segment_measurement_label_color(...)` сразу меняет цвет подписи отрезка.
- После перемещения точек цвет подписей не сбрасывается.
- После перестроения измерений цвет подписей не сбрасывается.
- Canvas record round-trip не теряет `label_color`.
- Старые canvas record-структуры без `label_color` продолжают работать.

Требования к UI-тестам:
- В свойствах каждого угла поле `Цвет подписей` находится сразу после `Цвет линии`.
- В свойствах каждого отрезка поле `Цвет подписей` находится сразу после `Цвет линии`.
- Цветовая кнопка угла показывает текущий `label_color`.
- Цветовая кнопка отрезка показывает текущий `label_color`.
- Выбор нового цвета подписей угла обновляет модель, canvas и JSON.
- Выбор нового цвета подписей отрезка обновляет модель, canvas и JSON.
- Отмена диалога выбора цвета не меняет модель.
- Выбор того же цвета не запускает лишнее сохранение.
- После повторного открытия проекта цвета подписей видны в свойствах и применены на canvas.
- Существующие тесты для `Цвет линии`, имени, примечания, оценок, подписей точек и удаления измерений продолжают проходить.

Критерии приёмки:
- В свойствах угла есть настройка `Цвет подписей` сразу после `Цвет линии`.
- В свойствах отрезка есть настройка `Цвет подписей` сразу после `Цвет линии`.
- Изменение цвета подписей угла сразу меняет подпись угла на canvas.
- Изменение цвета подписей отрезка сразу меняет подпись отрезка на canvas.
- Цвет подписей сохраняется в JSON проекта и восстанавливается после повторного открытия.
- Старые проекты без `label_color` открываются без ошибок и получают default-цвета.
- Цвет линии и цвет подписей работают независимо.
- Геометрия, имена, примечания, подписи точек, оценки, видимость, удаление и переключение изображений продолжают работать.
- Существующие тесты проходят; добавлены или обновлены тесты для нового цвета подписей.
