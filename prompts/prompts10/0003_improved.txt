Задача: доработать работу со средним цветом изображения и командой `Выровнять фон`.

Исходная формулировка:
"В этом промпте будет несколько фиксов
1. При экспорте в эксель своств изображения если выбрано поле "Средний цвет" в месте со значениями rgb сделай отдельную пустую ячейку и окрась ее фон в полученный цвет
2. В Свойствах изображения при нажатии на значение поля "Средний цвет" предложить сохранить картинку в формате png квадрат с разрешением 100 на 100 в цвете среднего цвета
3. При при подаче команды "Выровнять фон" необходимо сразу сохранить изменения канваса в обрабатываемый файл (предварительно выдать сообщение что исходное изображение будет изменено и сохранено с возможностью отказаться)"

Контекст проекта:
- MagicBorder - настольное приложение на PyQt5.
- Панель `Свойства изображения` и команды интерфейса находятся в `src/magicborder/main_window.py`.
- Запись `.xlsx` выполняется собственным XML-writer в `src/magicborder/io_utils.py` через `write_xlsx_table(...)`.
- Экспорт свойств выбранного изображения вызывается командой `Экспорт свойств изображения в Excel`.
- Строки экспорта свойств изображения формируются в `MainWindow._image_property_export_rows(...)`.
- Значение `Средний цвет` находится в группе `Цветовое пространство RGB` и сейчас экспортируется как строка вида `RGB(10, 20, 30)`.
- В панели свойств для среднего цвета уже есть цветовой образец `average_color_swatch`.
- Команда `Выровнять фон` вызывает `MainWindow.flatten_background()` и применяет `ImageCanvas.flatten_background_to_white()`.
- Canvas хранит текущее изображение как RGB-массив и умеет возвращать его через `ImageCanvas.current_rgb_array()`.

Главное требование:
- Если средний цвет известен, пользователь должен видеть и получать не только текст `RGB(...)`, но и удобный визуальный образец цвета:
  - в Excel-экспорте свойств изображения;
  - через сохранение отдельного PNG-сэмпла из панели `Свойства изображения`.
- Команда `Выровнять фон` должна после подтверждения пользователя сразу сохранять изменённые пиксели в исходный файл текущего изображения проекта.

Часть 1. Excel-экспорт среднего цвета:
- При экспорте `Свойства изображения` в Excel, если среди выбранных свойств есть `average_color` / `Средний цвет`, рядом со значением RGB нужно добавить отдельную ячейку-образец.
- Рекомендуемый формат строки:
  - колонка `Свойство`: `Средний цвет`;
  - колонка `Значение`: `RGB(10, 20, 30)`;
  - новая дополнительная колонка, например `Цвет`: пустой текст, но фон ячейки залит цветом `#0A141E` для `RGB(10, 20, 30)`.
- Дополнительная колонка должна появляться только там, где это нужно для экспорта среднего цвета, но итоговый `.xlsx` должен оставаться корректным для всех строк.
- Если `Средний цвет` не выбран, структура существующих экспортов по возможности не должна меняться.
- Если средний цвет неизвестен, находится в состоянии расчёта или имеет значение `-`, ячейку-образец не окрашивать и не подставлять некорректный цвет.
- Не парсить RGB из произвольной локализованной строки, если можно передать структурированное значение из расчётов/состояния панели.
- При добавлении стилей заливки расширить существующий `write_xlsx_table(...)`, не добавлять тяжёлую Excel-зависимость ради одной заливки.
- Стили групповых строк, которые уже делаются жирными через `bold_rows`, должны сохраниться.
- Новая заливка не должна ломать существующие стили:
  - заголовки;
  - жирные строки групп;
  - обычные строки.
- Цвет ячейки в OOXML должен записываться как валидный RGB/ARGB hex, понятный Excel/LibreOffice.

Требования к API Excel-writer:
- Расширить `write_xlsx_table(...)` аккуратно и обратно совместимо.
- Возможный вариант: добавить необязательный параметр с map стилей ячеек или map заливок по координатам/ключам строк.
- Старые вызовы `write_xlsx_table(...)` должны продолжить работать без изменений.
- Тестовые helper-функции, которые читают `.xlsx` как zip с XML, должны по-прежнему видеть строки и стили.
- Не менять формат файла с `.xlsx` на CSV или другой формат.

Часть 2. Сохранение PNG среднего цвета из панели свойств:
- В панели `Свойства изображения` сделать значение/образец `Средний цвет` кликабельным.
- При клике по `Средний цвет`, если цвет рассчитан, открыть стандартный диалог сохранения файла:
  - заголовок: `Сохранить средний цвет`;
  - фильтр: `PNG (*.png);;All files (*)`;
  - имя по умолчанию можно сформировать от имени изображения, например `<image_stem>_average_color.png`.
- Если пользователь выбрал путь без расширения, добавить `.png`.
- Сохранить PNG размером ровно `100 x 100` пикселов.
- Все пиксели PNG должны быть залиты средним RGB-цветом текущего выбранного изображения/контура.
- Если средний цвет ещё не рассчитан, нет изображения, нет контура или значение находится в состоянии расчёта, показать понятное предупреждение и не открывать диалог сохранения.
- При отмене диалога файл не создавать.
- При ошибке записи показать сообщение об ошибке в стиле существующих `_show_error(...)`.
- После успешного сохранения показать status-bar сообщение.
- UX должен быть очевидным:
  - курсор или tooltip у `average_color_swatch` должен подсказывать, что образец можно сохранить;
  - клик не должен менять проект, аннотацию или изображение.

Рекомендуемая реализация PNG:
- Использовать уже имеющуюся зависимость Pillow, если она используется в проекте.
- Создать `Image.new("RGB", (100, 100), (red, green, blue))` и сохранить как PNG.
- Не делать скриншот виджета и не сохранять scaled swatch: нужен чистый квадрат `100 x 100`.

Часть 3. `Выровнять фон` с сохранением исходного файла:
- Перед выполнением `Выровнять фон` показать подтверждение пользователю.
- Текст предупреждения должен явно говорить, что исходный файл изображения будет изменён и сохранён на диск.
- Пользователь должен иметь возможность отказаться.
- Если пользователь отказался:
  - canvas не менять;
  - файл изображения не менять;
  - проект не сохранять из-за этой команды.
- Если пользователь подтвердил:
  - выполнить текущую операцию выравнивания фона;
  - сохранить изменённый RGB-массив canvas в файл текущего изображения проекта;
  - обновить состояние canvas и свойства так, чтобы средние цвета/гистограммы соответствовали изменённому изображению;
  - сохранить/запланировать сохранение проекта только там, где это действительно нужно для актуализации состояния проекта.
- Сохранять нужно именно в обрабатываемый файл текущего изображения проекта, а не в JSON проекта и не в отдельный новый файл.
- Если исходный файл отсутствует, недоступен для записи или формат не поддерживает сохранение, показать ошибку и не делать вид, что операция завершена.
- Если сохранение файла после изменения canvas не удалось, показать ошибку; желательно не оставлять пользователя в уверенности, что файл на диске обновлён.
- При успешном завершении status-bar сообщение должно отражать, что фон выровнен и изображение сохранено.

Требования к сохранению изменённого изображения:
- Использовать путь текущего проектного изображения через существующий record/path helper, а не путь из UI-текста.
- Сохранять RGB-данные без альфа-канала, если исходный рабочий массив RGB.
- Для PNG/JPEG и других поддерживаемых Pillow форматов сохранить обычным способом.
- Для JPEG учитывать, что формат сжатый: тесты не должны требовать побитового совпадения для JPEG.
- Для PNG в тестах можно проверять точные пиксели.
- Не добавлять отдельную команду `Сохранить изображение`, если задача требует только автоматического сохранения после `Выровнять фон`.

Не входит в задачу:
- Не менять алгоритм расчёта среднего цвета.
- Не менять алгоритм построения контура.
- Не менять саму операцию выравнивания фона, кроме подтверждения и сохранения результата в файл.
- Не менять JSON-формат проекта без необходимости.
- Не менять экспорт списка изображений в Excel.
- Не добавлять новые цветовые пространства.
- Не менять названия существующих RGB-полей `Красный`, `Зелёный`, `Синий`, `Средний цвет`.
- Не добавлять обязательную зависимость `openpyxl`, если текущий writer можно расширить.

Требования к тестам Excel:
- Экспорт выбранных свойств `red`, `green`, `blue`, `average_color` по-прежнему содержит строки групп:
  - `Цветовые пространства`;
  - `Цветовое пространство RGB`;
  - `Красный`;
  - `Зелёный`;
  - `Синий`;
  - `Средний цвет`.
- Для `Средний цвет` значение остаётся текстом `RGB(10, 20, 30)`.
- В строке `Средний цвет` появляется отдельная ячейка-образец с пустым текстом и заливкой цвета `10, 20, 30`.
- В XML `.xlsx` есть стиль/fill для этого цвета.
- Групповые строки остаются жирными.
- Если `average_color` не выбран, старый экспорт без этой строки не получает лишних цветовых данных.
- Если средний цвет неизвестен, export не падает и не создаёт некорректный fill.

Требования к UI-тестам PNG-сэмпла:
- Клик по `average_color_swatch` при рассчитанном цвете открывает диалог сохранения PNG.
- При выборе пути сохраняется файл `100 x 100` с нужным RGB-цветом.
- При пути без расширения добавляется `.png`.
- При отмене диалога файл не создаётся.
- Если цвет неизвестен, показывается предупреждение и диалог сохранения не открывается.
- Клик по swatch не меняет данные проекта и не запускает лишнее сохранение проекта.

Требования к тестам `Выровнять фон`:
- Перед изменением изображения вызывается подтверждение.
- При отказе пользователя canvas и файл изображения остаются без изменений.
- При подтверждении фон за пределами контура становится белым на canvas.
- После подтверждения изменённое изображение сохраняется в исходный файл.
- Для PNG-файла тест проверяет пиксели на диске после выполнения команды.
- При ошибке сохранения показывается ошибка.
- Если нет выбранного изображения или нет контура, существующие предупреждения продолжают работать.

Проверки перед завершением:
- Запустить синтаксическую проверку:
  - `python -m compileall src tests`
- Запустить релевантные тесты:
  - `tests/test_project_properties.py`
  - `tests/test_canvas.py`
- Если полный набор тестов слишком долгий, запустить хотя бы новые/изменённые тесты вокруг:
  - экспорта свойств изображения в Excel;
  - сохранения PNG среднего цвета;
  - команды `Выровнять фон`.

Ожидаемый результат:
- В `Экспорт свойств изображения в Excel` строка `Средний цвет` остаётся текстово понятной и дополнительно содержит цветовой образец.
- В `Свойствах изображения` пользователь может сохранить средний цвет как PNG-квадрат `100 x 100`.
- `Выровнять фон` предупреждает о перезаписи исходного изображения, выполняется только после подтверждения и сохраняет изменённое изображение в файл.
