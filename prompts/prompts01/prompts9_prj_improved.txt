Переделай приложение так, чтобы оно работало не с одним изображением, а с проектом, содержащим набор изображений и их аннотации.

Главная цель:
   - Реализовать пакетную работу с изображениями внутри одного проекта.
   - Все данные проекта, включая список изображений и аннотации контуров для каждого изображения, должны храниться в одном JSON-файле проекта.
   - Изображения, добавленные в проект, должны храниться рядом с JSON-файлом проекта в папке проекта.
   - Уже реализованный функционал загрузки изображения, отображения, редактирования контура, сохранения аннотаций, анализа и гистограмм должен продолжить работать для текущего выбранного изображения.

Формат проекта:
   - Проект должен быть папкой на диске.
   - При создании нового проекта приложение должно создавать папку проекта с именем проекта.
   - Внутри папки проекта должен находиться JSON-файл проекта.
   - Внутри этой же папки или в отдельной подпапке проекта должны храниться файлы изображений, добавленные в проект.
   - Формат JSON должен быть расширяемым и понятным.
   - В JSON нужно хранить:
     - имя проекта;
     - версию формата проекта;
     - список изображений;
     - относительный путь к каждому изображению внутри папки проекта;
     - отображаемое имя изображения;
     - размер изображения, если это удобно для проверки целостности;
     - аннотацию контура для каждого изображения;
     - дополнительные данные, которые уже есть в текущем формате аннотаций и нужны существующему функционалу.
   - Пути к изображениям в JSON должны быть относительными, чтобы папку проекта можно было переносить.
   - Если у изображения ещё нет разметки, в JSON всё равно должна быть запись об изображении, но аннотация может быть пустой.
   - Если в проекте уже существует формат JSON-аннотации, используй его как основу для хранения аннотаций отдельных изображений, чтобы не переписывать лишнюю логику.

Команды проекта:
   - Добавь команду "Новый проект".
   - Добавь команду "Открыть проект".
   - Добавь команду "Сохранить проект", если проект не сохраняется автоматически во всех нужных местах.
   - Добавь команду "Закрыть проект".
   - Команды должны быть доступны через меню приложения.
   - Если в приложении уже есть панель инструментов, добавь туда основные команды проекта по стилю существующих действий.
   - Для команд должны быть русские названия, tooltip и status tip.
   - Если в проекте есть система иконок, используй её и добавь иконки в стиле существующих.

Создание нового проекта:
   - Пользователь выбирает имя и расположение нового проекта.
   - Приложение создаёт папку проекта.
   - В папке создаётся JSON-файл проекта.
   - После создания новый проект становится текущим открытым проектом.
   - Интерфейс очищается от данных предыдущего проекта.
   - Список изображений сначала пустой.
   - Заголовок окна должен показывать имя открытого проекта, например `MagicBorder - my_project`.

Открытие проекта:
   - Пользователь выбирает JSON-файл проекта.
   - Приложение загружает список изображений и аннотации.
   - В левой панели должен отобразиться список изображений проекта.
   - Если в проекте есть изображения, можно автоматически выбрать первое изображение или оставить выбор пустым, но поведение должно быть предсказуемым.
   - Если файл изображения из проекта не найден на диске, приложение не должно падать.
   - Для отсутствующего изображения нужно показать понятное состояние ошибки в списке или в свойствах.
   - Заголовок окна должен обновиться и показывать имя открытого проекта.

Закрытие проекта:
   - Команда закрывает текущий проект.
   - Перед закрытием нужно сохранить изменения или спросить пользователя о сохранении, если в приложении уже есть модель несохранённых изменений.
   - После закрытия проекта список изображений, свойства и основная область изображения должны быть очищены.
   - Команды, требующие открытого проекта, должны стать недоступными.
   - Заголовок окна должен вернуться к базовому виду `MagicBorder`.

Добавление изображений в проект:
   - Добавь команду "Добавить изображения".
   - Пользователь может выбрать один или несколько файлов изображений.
   - Выбранные файлы нужно скопировать в папку проекта или в проектную подпапку для изображений.
   - В JSON проекта нужно добавить записи для всех добавленных изображений.
   - Добавленные изображения должны сразу появиться в списке в левой панели.
   - Если изображение с таким именем уже есть в папке проекта, нужно избежать перезаписи:
     - либо предложить пользователю действие;
     - либо автоматически создать безопасное уникальное имя файла.
   - Поддержи те форматы изображений, которые уже поддерживает приложение.
   - Если часть файлов не удалось добавить, приложение должно добавить остальные и показать понятное сообщение об ошибках.

Удаление изображений из проекта:
   - Добавь команду "Удалить изображение из проекта".
   - Команда удаляет выбранное изображение из списка проекта и из JSON.
   - Нужно явно определить поведение с физическим файлом изображения:
     - предпочтительно спросить пользователя, удалить ли файл с диска или только убрать его из проекта;
     - если в приложении уже есть похожее соглашение, следуй ему.
   - После удаления выбранного изображения основная область и окно свойств должны обновиться.
   - Если удалено текущее изображение, нужно выбрать соседнее изображение или очистить выбор.
   - Удаление не должно повреждать аннотации остальных изображений.

Левая панель проекта:
   - В левой части интерфейса добавь проектную панель.
   - Между проектной панелью и основной областью изображения должен быть вертикальный перетаскиваемый разделитель.
   - Проектная панель должна быть разделена на две части горизонтальным перетаскиваемым разделителем.
   - В верхней части расположен список изображений проекта.
   - В нижней части расположено окно свойств выбранного изображения.
   - Разделители должны сохранять удобные размеры по умолчанию и корректно работать при изменении размера окна.
   - Интерфейс не должен ломаться, если список изображений пустой.

Список изображений:
   - В списке должны отображаться все изображения, добавленные в проект.
   - Для каждого изображения желательно показывать:
     - имя файла;
     - признак наличия аннотации;
     - признак отсутствующего файла, если файл не найден;
     - признак несохранённых изменений, если такая модель будет реализована.
   - При выборе элемента списка соответствующее изображение должно открываться в основной области.
   - Если у изображения есть аннотация в JSON проекта, контур должен автоматически загрузиться и отобразиться поверх изображения.
   - Если аннотации нет, изображение открывается без контура, но пользователь может создать новый контур существующими инструментами.
   - Переключение между изображениями не должно терять изменения контура.

Окно свойств изображения:
   - В нижней части левой панели показывай свойства выбранного изображения.
   - Минимальный набор свойств:
     - имя файла;
     - относительный путь внутри проекта;
     - размер изображения;
     - наличие или отсутствие аннотации;
     - количество точек контура, если контур есть;
     - для контура среднее значение красного канала (от 0 до 255);
     - для контура среднее значение зеденого канала (от 0 до 255);
     - для контура среднее значение синего канала (от 0 до 255);
     - прямоугольник залитый средним цветом контура;
     - статус файла: найден или отсутствует.
   - Если изображение не выбрано, покажи аккуратное пустое состояние.
   - Если изображение отсутствует на диске, свойства должны показывать проблему без аварийного завершения приложения.
   - Предусмотри кнопку обновления свойств изображения.

Работа с контуром и аннотациями:
   - Для выбранного изображения должен сохраниться весь уже реализованный функционал редактирования контура.
   - При создании, изменении, перемещении или удалении точек контура данные должны сохраняться в JSON текущего проекта.
   - При переключении на другое изображение текущая аннотация должна быть сохранена в структуре проекта.
   - При повторном выборе изображения его контур должен восстановиться из JSON проекта.
   - Если пользователь меняет контур, связанные панели анализа и гистограмм должны обновляться так же, как раньше.
   - Не нужно больше хранить отдельные JSON-аннотации для каждого изображения, если это противоречит новой проектной модели.
   - Если старые команды загрузки или сохранения отдельной аннотации остаются в приложении, они не должны конфликтовать с проектным JSON.

Поведение существующих функций:
   - Текущие команды открытия одиночного изображения можно сохранить, но они должны быть согласованы с проектным режимом.
   - Если проект открыт, добавление изображения в проект должно быть основным сценарием.
   - Сохранение изображения, работа с контуром, аналитика и гистограммы должны применяться к текущему выбранному изображению.
   - При смене изображения должны сбрасываться только данные, относящиеся к прошлому текущему изображению на экране; данные проекта не должны теряться.
   - Не ломай существующие горячие клавиши, меню и панели инструментов.

Сохранение проекта:
   - JSON проекта должен обновляться после изменений состава проекта и аннотаций.
   - Если используется автосохранение, оно должно быть аккуратным и не приводить к потере данных при ошибке записи.
   - Предпочтительно сохранять через временный файл и атомарную замену, если это удобно в текущем стеке.
   - При ошибке сохранения нужно показать пользователю понятное сообщение.
   - После успешного сохранения состояние проекта должно считаться актуальным.

Требования к реализации:
   - Используй существующие классы, сигналы, QAction, QSplitter, модель отображения изображения и механизм работы с контуром.
   - Не дублируй логику сериализации контура: лучше адаптировать текущие функции сохранения и загрузки аннотаций для работы внутри JSON проекта.
   - Для списка изображений используй подходящую модель/виджет из текущего GUI-стека проекта.
   - Держи проектные пути относительными к папке проекта.
   - Не допускай падения приложения при пустом проекте, отсутствующем файле изображения или повреждённой записи в JSON.
   - Все пользовательские сообщения должны быть на русском языке.
   - Код должен оставаться совместимым с текущей архитектурой приложения.

Критерии готовности:
   - Можно создать новый проект, и на диске появляется папка проекта с JSON-файлом.
   - Можно открыть существующий JSON-файл проекта.
   - Можно закрыть проект, после чего интерфейс очищается.
   - Можно добавить несколько изображений в проект за одну операцию.
   - Добавленные изображения копируются в папку проекта и появляются в списке.
   - Можно удалить изображение из проекта без повреждения остальных записей.
   - Слева появилась панель проекта с вертикальным разделителем относительно основной области.
   - Внутри левой панели есть верхний список изображений и нижняя панель свойств, разделённые горизонтальным разделителем.
   - При выборе изображения оно отображается в основной области.
   - Если у изображения есть сохранённый контур, он автоматически загружается из JSON проекта и отображается поверх изображения.
   - При изменении контура изменения сохраняются в JSON проекта.
   - При переключении между изображениями контуры восстанавливаются корректно.
   - Свойства выбранного изображения отображаются в нижней части левой панели.
   - Проект с несколькими изображениями можно закрыть, снова открыть и получить тот же список изображений и те же контуры.
   - Отсутствующий файл изображения в проекте не приводит к падению приложения.
   - Все существующие функции для текущего изображения продолжают работать.
