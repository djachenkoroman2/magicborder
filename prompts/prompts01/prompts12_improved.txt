Доработай проектный режим приложения: добавь редактируемый идентификатор изображения и экспорт сводной таблицы проекта в CSV.

Главная цель:
   - Для каждого изображения проекта должен быть пользовательский идентификатор `ID`.
   - `ID` должен отображаться и редактироваться в окне свойств выбранного изображения.
   - При изменении `ID` нужно проверять уникальность внутри текущего проекта.
   - В панели проекта должна появиться команда экспорта CSV со сводной информацией по изображениям проекта.

Поле ID:
   - Добавь в окно свойств изображения поле `ID`.
   - Поле должно быть редактируемым.
   - Значение должно сохраняться в JSON проекта.
   - Если в модели проекта уже есть техническое поле `id`, нужно явно решить, использовать его как пользовательский `ID` или добавить отдельное поле в `metadata`, например `sample_id`.
   - Предпочтительно не смешивать внутренний технический `id` записи и пользовательский идентификатор:
     - технический `id` нужен для стабильной работы списка и выбора записи;
     - пользовательский `ID` нужен для экспорта и работы пользователя.
   - Если добавляется отдельное поле, храни его в `metadata`, например:
     - `metadata.sample_id`.
   - Для старых проектов без пользовательского ID нужно подставлять безопасное значение по умолчанию:
     - либо пустую строку;
     - либо текущее техническое `id`, если это лучше для совместимости.

Редактирование ID:
   - При редактировании `ID` значение должно записываться в текущую запись изображения.
   - Изменение должно сохраняться в JSON проекта через существующий механизм автосохранения или команду "Сохранить проект".
   - `ID` не должен быть пустым, если он используется в CSV как обязательное поле.
   - При попытке сохранить пустой `ID` нужно показать понятное сообщение и вернуть старое значение.
   - `ID` должен быть уникальным среди всех изображений текущего проекта.
   - Проверка уникальности должна учитывать все записи проекта, кроме текущей.
   - Сравнение лучше делать после удаления пробелов по краям.
   - Если пользователь ввёл уже занятый `ID`, нужно показать сообщение на русском языке и вернуть прежнее значение.
   - После успешного изменения `ID` окно свойств и JSON проекта должны обновиться.

Панель проекта и команда CSV:
   - В левой проектной панели добавь кнопку или команду экспорта CSV.
   - Команда должна быть доступна только когда открыт проект.
   - Кнопку можно разместить рядом с заголовком списка изображений проекта или в нижней части проектной панели.
   - Для команды добавь русские tooltip и status tip.
   - Если в приложении есть система SVG-иконок, добавь отдельную SVG-иконку в стиле проекта.
   - Команда должна также быть доступна в меню, если это соответствует текущей структуре приложения.

Выбор файла CSV:
   - При запуске команды открывай диалог сохранения файла.
   - Фильтр файла должен предлагать `CSV (*.csv)`.
   - Если пользователь ввёл имя без расширения, приложение должно добавить `.csv`.
   - Если пользователь отменил диалог, экспорт не выполняется.
   - После успешного экспорта нужно показать сообщение в status bar или информационный диалог.
   - При ошибке записи нужно показать понятное сообщение об ошибке.

Содержимое CSV:
   - В каждой строке CSV должна быть информация об одном изображении проекта.
   - Заголовок CSV должен быть включён.
   - Минимальные колонки:
     - `id` - пользовательский ID изображения;
     - `file_name` - имя файла изображения;
     - `r` - среднее значение красного канала внутри контура;
     - `g` - среднее значение зелёного канала внутри контура;
     - `b` - среднее значение синего канала внутри контура;
     - `contour_pixel_count` - количество пикселов внутри контура.
   - Значения `R`, `G`, `B` должны соответствовать тем же расчётам, что отображаются в окне свойств выбранного изображения.
   - `contour_pixel_count` должен соответствовать свойству "Количество пикселов контура".
   - Желательно добавить дополнительные полезные колонки:
     - `relative_path`;
     - `has_annotation`;
     - `status`;
     - `diagnosis`, если он уже хранится в metadata.
   - Если дополнительные колонки добавляются, они должны быть документированы в коде или README.

Расчёт статистики для CSV:
   - Экспорт должен пройти по всему списку изображений проекта.
   - Для каждого изображения нужно загрузить файл изображения с диска.
   - Если у изображения есть контур в JSON проекта, нужно рассчитать статистику по пикселям внутри этого контура.
   - Если контур отсутствует, значения `r`, `g`, `b` и `contour_pixel_count` можно оставить пустыми.
   - Если файл изображения отсутствует или повреждён, строку всё равно нужно добавить в CSV, но в статусе указать проблему.
   - Приложение не должно падать из-за одного проблемного изображения.
   - Если контур выходит за границы изображения, расчёт должен учитывать только существующие пикселы изображения, как в текущем механизме анализа.
   - Расчёт должен использовать существующие функции canvas/маски/аннотаций, если это возможно без переключения UI на каждое изображение.
   - Если проще использовать временный расчёт через существующий код маски, вынеси общий helper, чтобы не дублировать логику.

Формат CSV:
   - Используй стандартный модуль `csv`, а не ручную склейку строк.
   - Кодировка файла должна быть `utf-8`.
   - Для совместимости с Excel можно использовать `utf-8-sig`, если это принято в проекте.
   - Разделитель можно использовать стандартный `,`.
   - Все строки должны корректно экранироваться через `csv.DictWriter` или аналогичный API.
   - Числовые значения `r`, `g`, `b` можно записывать как целые числа `0..255`, округлённые так же, как в окне свойств.

Интеграция с существующими свойствами:
   - Поле `ID` должно отображаться вместе с остальными редактируемыми метаданными.
   - Кнопка "Обновить свойства" не должна стирать `ID`.
   - При переименовании файла `ID` не должен меняться.
   - При удалении контура `ID` должен сохраняться.
   - При удалении изображения из проекта соответствующий `ID` освобождается.

Требования к реализации:
   - Не ломай существующий JSON проекта.
   - Старые проекты без пользовательского ID должны открываться без ошибок.
   - Не ломай добавление и удаление изображений.
   - Не ломай редактирование и сохранение метаданных.
   - Не ломай создание, удаление и редактирование контура.
   - Все новые пользовательские сообщения должны быть на русском языке.
   - Код должен соответствовать текущей архитектуре PyQt5-приложения.

Критерии готовности:
   - В окне свойств есть редактируемое поле `ID`.
   - `ID` сохраняется в JSON проекта.
   - После закрытия и открытия проекта `ID` восстанавливается.
   - Нельзя задать двум изображениям одинаковый `ID`.
   - При попытке задать дублирующийся `ID` пользователь получает понятное предупреждение.
   - В проектной панели есть команда экспорта CSV.
   - При экспорте пользователь выбирает имя CSV-файла через диалог.
   - CSV содержит заголовок и строку для каждого изображения проекта.
   - Для изображений с контуром CSV содержит `id`, `file_name`, `r`, `g`, `b`, `contour_pixel_count`.
   - Для изображений без контура CSV создаётся без падения, а статистические поля остаются пустыми.
   - Для отсутствующих файлов CSV создаётся без падения, а статус строки отражает проблему.
   - Значения RGB и количества пикселов совпадают с тем, что показывает окно свойств для выбранного изображения.
