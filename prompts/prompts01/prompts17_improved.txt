Добавь в проектный режим MagicBorder команду синхронизации папки изображений: команда должна найти в папке изображений текущего проекта все совместимые растровые файлы, которых ещё нет в JSON проекта, и добавить их в список изображений проекта без автоматического построения контура.

Главная цель:
   - Для текущего открытого проекта нужна новая команда `Синхронизировать папку изображений` или аналогичная по смыслу.
   - Команда должна просканировать папку, где проект хранит изображения.
   - Нужно найти все файлы с поддерживаемыми расширениями, которые физически лежат в этой папке, но отсутствуют в `ProjectDocument.images`.
   - Найденные файлы нужно добавить в JSON проекта как новые `ProjectImageRecord`.
   - Автоматический контур для добавленных изображений строить не нужно.
   - Команда должна быть доступна из меню и с основной кнопочной панели.
   - Для команды нужно добавить отдельную SVG-иконку в стиле текущих иконок проекта.

Контекст текущей архитектуры:
   - Проект хранится как `ProjectDocument`.
   - Папка изображений проекта задаётся через `project_document.images_dir`, обычно `images`.
   - Абсолютный путь к папке изображений можно получить от `project_path.parent / project_document.images_dir`.
   - Записи изображений представлены `ProjectImageRecord`.
   - Поддерживаемые расширения уже описаны в `SUPPORTED_RASTER_SUFFIXES`.
   - Для проверки, что файл действительно можно открыть как изображение, используй существующий `load_raster_image(...)`.
   - Для записи относительного пути используй существующий helper `portable_path_reference(...)`.
   - Для новых записей используй текущие правила проекта:
     - `record.id` должен быть новым уникальным GUID/UUID4;
     - `display_name` должен быть именем файла;
     - `relative_path` должен быть переносимым относительным путём от папки проекта;
     - `image_width` и `image_height` должны браться из файла;
     - `metadata` должны создаваться через `default_project_image_metadata(...)`;
     - `metadata.added_at` нужно заполнить текущим временем так же, как при обычном добавлении изображений;
     - `metadata.captured_at` можно прочитать через `read_image_captured_at(...)`, если это уже используется в обычном добавлении.

Что считать уже добавленным:
   - Файл считается уже входящим в проект, если его путь совпадает с `relative_path` одной из записей проекта.
   - Сравнение путей должно быть устойчивым:
     - нормализуй разделители `/` и `\`;
     - сравнивай относительные пути от папки проекта;
     - не полагайся только на `display_name`, потому что в будущем возможны подпапки или одинаковые имена.
   - Если в JSON есть запись на отсутствующий файл, эта запись всё равно считается проектной записью и не должна дублироваться при совпадении пути.
   - Если физический файл имеет то же имя, но другой относительный путь, добавляй его как отдельную запись только если сканирование подпапок включено.

Область сканирования:
   - Минимально нужно просканировать непосредственное содержимое папки `images`.
   - Если удобнее и безопасно для проекта, можно просканировать папку рекурсивно, но это нужно сделать явно и покрыть тестом.
   - Предпочтительный вариант: рекурсивно искать файлы внутри `project_document.images_dir`, потому что это лучше поддерживает вложенные папки.
   - Не выходи за пределы папки изображений проекта.
   - Не сканируй папку проекта целиком, если она не является папкой изображений.
   - Не добавляй JSON, CSV, аннотации и любые нерастровые файлы.

Поведение команды:
   - Если проект не открыт, команда должна быть недоступна.
   - Если проект открыт, команда должна быть доступна в меню и toolbar.
   - При запуске команды:
     - сохрани текущую аннотацию через существующий механизм, если это нужно для консистентности;
     - убедись, что папка изображений проекта существует;
     - если папка отсутствует, создай её или покажи понятную ошибку на русском языке, выбрав поведение, наиболее близкое текущей логике добавления изображений;
     - просканируй файлы с расширениями из `SUPPORTED_RASTER_SUFFIXES`;
     - пропусти файлы, которые уже есть в `project_document.images`;
     - для каждого нового валидного изображения создай запись проекта;
     - не создавай контур и не запускай автоматическое определение контура;
     - обнови список изображений проекта;
     - выбери первое добавленное изображение, если были добавлены новые файлы;
     - сохрани JSON проекта через существующий механизм;
     - покажи сообщение в status bar с количеством добавленных файлов.
   - Если новых файлов не найдено, покажи короткое сообщение в status bar, например `Новых изображений не найдено.`

Ошибки и частично проблемные файлы:
   - Если отдельный файл нельзя открыть как изображение, не прерывай всю команду.
   - Проблемный файл пропусти и добавь его в список ошибок.
   - После завершения покажи предупреждение на русском языке, если были файлы с ошибками.
   - В предупреждении можно показать первые несколько ошибок, как уже сделано в обычном добавлении изображений.
   - Один повреждённый или неподдерживаемый файл не должен мешать добавлению остальных валидных файлов.
   - Если возникла ошибка создания папки изображений или чтения директории, покажи понятную ошибку и не меняй проект.

Отличие от команды `Добавить изображения`:
   - Новая команда не должна открывать диалог выбора файлов.
   - Новая команда не должна копировать файлы из внешних папок.
   - Новая команда работает только с файлами, которые уже физически лежат в папке изображений текущего проекта.
   - Новая команда должна добавлять отсутствующие записи в JSON проекта.
   - Существующая команда `Добавить изображения...` должна продолжить работать как раньше.

Интерфейс:
   - Добавь новый `QAction`, например:
     - текст меню: `Синхронизировать папку изображений`;
     - tooltip: `Синхронизировать папку изображений`;
     - status tip: `Добавить в проект изображения из папки проекта, которых ещё нет в JSON.`
   - Добавь action в меню `Файл` рядом с командами добавления/удаления изображений и CSV-экспорта.
   - Добавь action на основную панель инструментов рядом с `Добавить изображения`.
   - Добавь action в `_apply_action_visuals(...)` и `ACTION_VISUALS`.
   - Добавь включение/выключение action в `_update_action_states(...)`:
     - включена только когда открыт проект.
   - Если в левой панели есть компактные кнопки проекта, добавлять туда необязательно, но можно, если это соответствует текущему UI.

Иконка:
   - Добавь отдельный SVG-файл в `src/magicborder/assets/icons/`.
   - Иконка должна быть уникальной и не копировать один в один существующую `add-images.svg`.
   - Визуальная идея: папка/изображения + знак обновления/синхронизации.
   - Используй стиль текущих иконок:
     - `32x32`;
     - `fill="none"`;
     - основные линии тёмно-синие;
     - акценты зелёно-бирюзовые;
     - скруглённые линии и углы.
   - Название иконки может быть `sync-images.svg`, `scan-images.svg` или другое понятное имя.

Данные новой записи:
   - `id`: новый уникальный GUID через существующий helper генерации ID проекта, если он уже есть.
   - `relative_path`: путь к файлу относительно папки проекта.
   - `display_name`: имя файла.
   - `image_width` и `image_height`: фактический размер изображения.
   - `annotation`: `None`.
   - `metadata`: значения по умолчанию через `default_project_image_metadata(...)`.
   - `added_at`: текущая дата и время.
   - `captured_at`: значение из EXIF через `read_image_captured_at(...)`, если доступно.
   - Не добавляй `metadata.sample_id` для новых записей, если проект уже перешёл на единый `record.id`.

Сохранение и состояние UI:
   - После добавления новых записей обнови список изображений проекта.
   - Если добавлены изображения, выбери первое из добавленных.
   - Обнови состояние actions и свойства выбранного изображения через уже существующие методы.
   - Сохрани проект в JSON.
   - Не сбрасывай текущий контур выбранного изображения без необходимости.
   - Если команда запускается во время открытого проекта с несохранённой текущей аннотацией, сначала используй существующий механизм сохранения текущей аннотации.

Совместимость:
   - Не меняй формат JSON проекта.
   - Не ломай открытие старых проектов.
   - Не ломай обычное добавление изображений через диалог.
   - Не ломай удаление изображений из проекта.
   - Не ломай CSV-экспорт.
   - Не ломай генерацию и редактирование ID.
   - Не ломай создание, редактирование и удаление контуров.
   - Все новые пользовательские сообщения должны быть на русском языке.
   - Код должен соответствовать текущей архитектуре PyQt5-приложения.

Критерии готовности:
   - В меню `Файл` появилась команда синхронизации папки изображений.
   - На основной toolbar появилась кнопка этой команды.
   - У команды есть уникальная SVG-иконка.
   - Команда недоступна, если проект не открыт.
   - При открытом проекте команда доступна.
   - Если в папке `images` лежит совместимый файл, которого нет в JSON проекта, команда добавляет его в `ProjectDocument.images`.
   - Для добавленного файла создаётся уникальный GUID `record.id`.
   - Для добавленного файла заполняются `relative_path`, `display_name`, `image_width`, `image_height` и метаданные по умолчанию.
   - Для добавленного файла не создаётся контур.
   - Уже учтённые в JSON файлы не дублируются.
   - Неподдерживаемые расширения не добавляются.
   - Повреждённые файлы не ломают всю синхронизацию.
   - После команды JSON проекта сохраняется.
   - После закрытия и повторного открытия проекта добавленные записи сохраняются.
   - Если новых файлов нет, пользователь получает понятное сообщение.
