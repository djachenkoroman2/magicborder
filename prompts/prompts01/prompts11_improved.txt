Доработай проектный режим приложения: добавь редактируемые метаданные для каждого изображения проекта в окно свойств.

Главная цель:
   - Для каждого изображения в проекте нужно хранить не только путь, размер и аннотацию, но и набор пользовательских метаданных.
   - Метаданные должны отображаться в окне свойств выбранного изображения.
   - Все добавленные поля должны редактироваться пользователем прямо в окне свойств.
   - Значения должны сохраняться в JSON проекта и восстанавливаться после закрытия и повторного открытия проекта.

Новые свойства изображения:
   - Дата и время добавления изображения в проект.
   - Дата и время съёмки.
   - Освещённость.
   - Влажность.
   - Скорость ветра.
   - Направление ветра.
   - Координаты места съёмки.
   - Диагноз болезни или принадлежность к классу.
   - Дополнительные сведения по изображению.
   - Имя файла изображения.

Хранение в JSON проекта:
   - Расширь запись изображения в JSON проекта, не ломая существующие поля.
   - Новые метаданные желательно хранить в отдельном объекте, например `metadata`.
   - В JSON для каждого изображения должны сохраняться:
     - `added_at` - дата и время добавления изображения в проект;
     - `captured_at` - дата и время съёмки;
     - `illumination` - освещённость;
     - `humidity` - влажность;
     - `wind_speed` - скорость ветра;
     - `wind_direction` - направление ветра;
     - `location` или отдельные поля `latitude` / `longitude` - координаты места съёмки;
     - `diagnosis` - диагноз болезни или класс;
     - `notes` - дополнительные сведения;
     - дополнительные поля, если они нужны для удобной реализации.
   - Формат должен быть расширяемым, чтобы позже можно было добавить новые свойства без миграции всего проекта.
   - При открытии старого проекта без `metadata` приложение должно работать без ошибок и подставлять значения по умолчанию.
   - Не удаляй неизвестные поля метаданных при сохранении проекта, если это удобно реализовать без усложнения архитектуры.

Значения по умолчанию:
   - При добавлении изображения в проект автоматически заполняй дату и время добавления.
   - Дату и время добавления нужно брать из текущего системного времени.
   - Формат хранения даты и времени должен быть стабильным, например ISO 8601.
   - Дата и время съёмки по умолчанию могут быть пустыми.
   - Если возможно и в проекте уже есть доступ к EXIF через текущие библиотеки, можно попытаться автоматически прочитать дату съёмки из EXIF.
   - Если EXIF отсутствует или чтение не реализуется просто, оставь поле даты съёмки пустым.
   - Освещённость, влажность, скорость ветра, направление ветра, координаты, диагноз и дополнительные сведения по умолчанию должны быть пустыми или иметь явно безопасное значение по умолчанию.
   - Для диагноза можно предусмотреть строку по умолчанию `Не указано`, если это лучше вписывается в UI.

Окно свойств:
   - В нижней части левой панели, где уже отображаются свойства выбранного изображения, добавь редактируемые поля.
   - Уже существующие вычисляемые свойства должны остаться видимыми:
     - размер изображения;
     - наличие аннотации;
     - количество узлов контура;
     - количество пикселов контура;
     - средние значения RGB;
     - средний цвет;
     - статус файла.
   - Новые пользовательские свойства должны быть редактируемыми.
   - Для коротких строк используй однострочные поля ввода.
   - Для дополнительных сведений используй многострочное поле.
   - Для даты и времени можно использовать:
     - `QDateTimeEdit`, если это удобно;
     - или обычное текстовое поле с понятным форматом, если так проще и ближе к текущей архитектуре.
   - Для числовых полей можно использовать `QDoubleSpinBox` / `QSpinBox` или строковые поля с валидацией.
   - Координаты можно реализовать как два отдельных поля:
     - широта;
     - долгота.
   - Поле диагноза можно реализовать как обычное редактируемое текстовое поле.

Редактирование и сохранение:
   - При изменении любого редактируемого поля значение должно записываться в текущую запись изображения проекта.
   - Изменения должны сохраняться в JSON проекта.
   - Если в проекте уже используется автосохранение, подключи новые поля к существующему механизму автосохранения.
   - Если есть команда "Сохранить проект", она также должна сохранять новые метаданные.
   - При переключении на другое изображение изменения текущих полей не должны теряться.
   - При повторном выборе изображения его метаданные должны отображаться из JSON проекта.

Изменение имени файла:
   - В окне свойств должна быть возможность изменить имя файла изображения.
   - Нужно определить безопасное поведение:
     - переименовать физический файл на диске в папке проекта;
     - обновить относительный путь в JSON проекта;
     - обновить отображаемое имя в списке изображений;
     - сохранить связь с аннотацией этого изображения.
   - Новое имя файла не должно быть пустым.
   - Новое имя должно сохранять допустимое расширение изображения.
   - Если пользователь ввёл имя без расширения, можно сохранить старое расширение.
   - Если файл с таким именем уже существует, нельзя молча перезаписывать его.
   - В случае конфликта имени нужно показать понятное сообщение и оставить старое имя.
   - Если физический файл отсутствует, разреши изменить только отображаемое имя или покажи понятное сообщение, но приложение не должно падать.

Валидация:
   - Влажность, если вводится числом, должна быть в диапазоне `0..100`.
   - Скорость ветра не должна быть отрицательной.
   - Широта должна быть в диапазоне `-90..90`.
   - Долгота должна быть в диапазоне `-180..180`.
   - Если используются текстовые поля, при некорректном вводе нужно показать сообщение или подсветить поле, но не сохранять некорректное значение как валидное число.
   - Если поле оставлено пустым, это должно быть допустимым состоянием.

Поведение интерфейса:
   - Окно свойств должно оставаться аккуратным и пригодным для работы при обычных размерах окна.
   - Если полей стало много, добавь прокрутку внутри панели свойств.
   - Подписи полей должны быть на русском языке.
   - Не должно быть наложения текста, кнопок и полей ввода.
   - Редактируемые поля должны визуально отличаться от вычисляемых read-only свойств.
   - Кнопка "Обновить свойства" должна продолжить обновлять вычисляемые свойства контура и изображения, не стирая пользовательские метаданные.

Требования к реализации:
   - Используй существующую модель проекта и запись изображения как основу.
   - Не ломай текущий JSON проекта: старые проекты должны открываться.
   - Не ломай добавление изображений в проект.
   - Не ломай удаление изображения из проекта.
   - Не ломай создание, удаление, редактирование и сохранение контура.
   - Не ломай отображение гистограмм и вычисляемых свойств контура.
   - Все пользовательские сообщения должны быть на русском языке.
   - Код должен соответствовать текущей архитектуре PyQt5-приложения.

Критерии готовности:
   - При добавлении изображения в проект в JSON появляется дата и время добавления.
   - В окне свойств выбранного изображения отображаются новые поля метаданных.
   - Новые поля можно редактировать.
   - После редактирования и переключения на другое изображение значения не теряются.
   - После закрытия и повторного открытия проекта значения восстанавливаются из JSON.
   - Можно изменить имя файла изображения через окно свойств.
   - При переименовании физический файл, относительный путь в JSON и список изображений обновляются согласованно.
   - Нельзя случайно перезаписать уже существующий файл при переименовании.
   - Старый проект без новых метаданных открывается без ошибок.
   - Вычисляемые свойства изображения и контура продолжают обновляться.
   - Кнопка обновления свойств работает и не очищает пользовательские метаданные.
   - Все существующие сценарии проектного режима продолжают работать.
