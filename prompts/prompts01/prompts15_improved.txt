Поменяй логику создания нового проекта в PyQt5-приложении MagicBorder: сначала пользователь вводит название проекта, затем выбирает папку, внутри которой будет создана вся папка проекта.

Главная цель:
   - При выборе команды `Файл -> Новый проект` первым должен открываться диалог ввода названия проекта.
   - Только после успешного ввода названия должен открываться диалог выбора родительской папки.
   - Выбранная папка должна быть именно родительской папкой, внутри которой приложение создаст отдельную папку проекта.
   - Все остальные правила создания проекта должны остаться такими же, как в текущей реализации.

Текущий контекст:
   - Сейчас `new_project()` сначала вызывает `QFileDialog.getExistingDirectory(...)`, а затем `QInputDialog.getText(...)`.
   - Нужно поменять этот порядок:
     - сначала `QInputDialog.getText(...)`;
     - потом `QFileDialog.getExistingDirectory(...)`.
   - Существующую функцию нормализации имени проекта, например `_safe_project_name(...)`, нужно сохранить и использовать.
   - Существующую модель `ProjectDocument` и сохранение через `save_project(...)` не меняй без необходимости.

Порядок работы команды:
   - Пользователь нажимает `Файл -> Новый проект`.
   - Приложение показывает диалог `Новый проект` с полем `Имя проекта:`.
   - Если пользователь нажал `Cancel`, создание проекта полностью отменяется.
   - Если пользователь ввёл пустое или некорректное имя, покажи существующее русское предупреждение или аналогичное сообщение:
     - `Некорректное имя`;
     - `Введите имя проекта.`
   - После корректного имени приложение показывает диалог выбора папки.
   - Заголовок диалога выбора папки должен ясно объяснять, что выбирается родительская папка, например:
     - `Выберите папку, где будет создан проект`;
     - или `Выберите папку для размещения проекта`.
   - Если пользователь отменил выбор папки, создание проекта полностью отменяется.
   - При отмене выбора папки не создавай папку проекта и не создавай JSON-файл.

Структура создаваемого проекта:
   - Пусть пользователь ввёл имя `Leaves 2026`.
   - После нормализации имени через существующие правила получается безопасное имя, например `Leaves_2026` или другой формат, который уже принят в проекте.
   - Если пользователь выбрал родительскую папку `/data/projects`, итоговая структура должна быть:
     - `/data/projects/<safe_name>/`;
     - `/data/projects/<safe_name>/images/`;
     - `/data/projects/<safe_name>/<safe_name>.json`.
   - Файл проекта должен оставаться внутри папки проекта.
   - Папка `images` должна создаваться внутри папки проекта.
   - `ProjectDocument.name` должен заполняться так же, как раньше: предпочтительно безопасным именем проекта, если это уже текущая логика.

Сохранение текущего проекта:
   - Не ломай существующее поведение при уже открытом проекте.
   - Перед переключением на новый проект нужно сохранить текущую аннотацию через существующий механизм, если он уже используется.
   - Перед переключением на новый проект нужно сохранить текущий проект через существующий механизм, если он уже используется.
   - Важно: если пользователь отменил ввод имени или выбор папки, не нужно сохранять/закрывать/переключать текущий проект только из-за открытия команды.
   - Сохранение текущего проекта лучше выполнять после успешного ввода имени и выбора папки, но до создания и открытия нового проекта.

Проверка конфликтов:
   - Если итоговая папка проекта уже существует и не пуста, покажи предупреждение на русском языке и не создавай проект.
   - Сохрани существующее сообщение или аналогичное:
     - `Папка уже существует`;
     - `Выберите другое имя проекта или пустую папку.`
   - Если папка проекта существует, но пуста, допускается использовать её, если это уже соответствует текущим правилам.
   - Нельзя молча перезаписывать существующий JSON-проект или чужие файлы.
   - При ошибке создания папок покажи понятное сообщение об ошибке на русском языке.
   - При ошибке сохранения JSON-файла покажи понятное сообщение об ошибке на русском языке.

Поведение при успешном создании:
   - Создай папку проекта и вложенную папку `images`.
   - Создай JSON-файл проекта.
   - Открой созданный проект в текущем окне через существующий путь, например `_set_project(...)`.
   - Обнови левую панель, список изображений, состояние actions, заголовок окна и status bar так же, как раньше.
   - В status bar должно появиться сообщение вроде `Создан проект: <safe_name>`.

Совместимость:
   - Не меняй формат JSON проекта.
   - Не ломай открытие существующих проектов.
   - Не ломай сохранение проекта.
   - Не ломай добавление изображений в проект.
   - Не ломай автосохранение аннотаций и метаданных.
   - Не меняй поведение одиночного открытия изображения вне проектного режима.
   - Все пользовательские сообщения должны оставаться на русском языке.
   - Код должен соответствовать текущей архитектуре `main_window.py`.

Критерии готовности:
   - При создании нового проекта первым открывается диалог ввода имени проекта.
   - Диалог выбора папки открывается только после успешного ввода корректного имени.
   - Если пользователь отменил ввод имени, диалог выбора папки не открывается.
   - Если пользователь отменил выбор папки, проект не создаётся.
   - Итоговая папка проекта создаётся внутри выбранной родительской папки.
   - Внутри папки проекта создаётся папка `images`.
   - JSON проекта создаётся внутри папки проекта и называется `<safe_name>.json`.
   - При существующей непустой папке проекта приложение показывает предупреждение и не перезаписывает файлы.
   - После успешного создания новый проект открыт в приложении.
   - Существующие сценарии открытия, сохранения и добавления изображений продолжают работать.
