Добавь команду "Новый контур", которая создаёт для текущего изображения новый контур в форме окружности.

Главная цель:
   - Пользователь должен иметь возможность быстро создать стартовый контур без автоматического распознавания.
   - Контур должен быть расположен в центре текущего изображения.
   - Контур должен состоять из заданного количества узлов, равномерно распределённых по окружности.
   - После создания этот контур должен редактироваться всеми уже существующими инструментами редактирования узлов.

Команда:
   - Добавь команду "Новый контур".
   - Команда должна быть доступна в меню "Инструменты".
   - Команда должна быть добавлена на основную панель инструментов, если в приложении уже есть toolbar.
   - Для команды должны быть русские tooltip и status tip.
   - Если в проекте используется система SVG-иконок, добавь отдельную SVG-иконку в стиле существующих иконок приложения.
   - Иконку нужно подключить через существующий механизм `ACTION_VISUALS` / `load_icon`, если он используется в проекте.
   - Для команды можно назначить свободную горячую клавишу, например `Ctrl+Shift+N`, если она не конфликтует с уже существующими shortcuts.

Диалог параметров:
   - При запуске команды показывай диалог для выбора количества узлов контура.
   - По умолчанию количество узлов должно быть `5`.
   - Минимальное допустимое количество узлов: `3`.
   - Максимальное допустимое количество узлов: разумное значение, например `128`, чтобы пользователь случайно не создал слишком тяжёлый контур.
   - Диалог должен быть на русском языке.
   - Название поля можно сделать таким:
     - `Количество узлов контура:`
   - Если пользователь нажал "Отмена", контур не должен создаваться и текущий контур не должен изменяться.

Построение контура:
   - Контур должен строиться в координатах изображения.
   - Центр окружности должен совпадать с центром изображения.
   - Радиус окружности должен подбираться так, чтобы весь контур гарантированно помещался внутри изображения.
   - Рекомендуемый радиус:
     - `0.35 * min(image_width, image_height)`.
   - Если изображение очень маленькое, радиус всё равно должен оставаться положительным и не выходить за границы изображения.
   - Узлы нужно распределить равномерно по окружности.
   - Порядок точек должен быть стабильным, например по часовой стрелке или против часовой стрелки.
   - Первая точка может располагаться сверху или справа от центра, но выбранное поведение должно быть предсказуемым.
   - Координаты точек должны быть совместимы с текущей моделью `Point` и существующей логикой `canvas.set_contour`.

Поведение при существующем контуре:
   - Если у текущего изображения уже есть контур, перед заменой нужно спросить пользователя подтверждение.
   - Текст подтверждения должен ясно говорить, что текущий контур будет заменён новым.
   - Если пользователь отказался, существующий контур должен остаться без изменений.
   - Если пользователь подтвердил замену, старый контур заменяется новым окружным контуром.

Проектный режим:
   - Если открыт проект и выбрано изображение проекта, новый контур должен сохраниться в JSON проекта для этого изображения.
   - После создания контура нужно обновить список изображений проекта, окно свойств, гистограммы и состояние команд.
   - При переключении на другое изображение и возврате новый контур должен восстанавливаться из JSON проекта.
   - Если проект не открыт, команда должна работать для одиночного текущего изображения так же, как существующее создание/загрузка контура.

Состояние команды:
   - Команда должна быть недоступна, если изображение не открыто.
   - Команда должна быть доступна, если изображение открыто, даже если проект не открыт.
   - После создания контура должны стать доступны команды, которые требуют наличия контура:
     - сохранение аннотации;
     - удаление контура;
     - выравнивание фона;
     - построение/сохранение гистограмм, если они зависят от контура.

Требования к реализации:
   - Используй существующую модель `Point`.
   - Используй существующий метод установки контура на canvas, например `canvas.set_contour(...)`.
   - Не дублируй логику сохранения аннотации в проекте: используй уже существующий механизм обновления текущей проектной записи, если он есть.
   - Не ломай команды:
     - "Определить контур";
     - "Удалить контур";
     - "Сохранить аннотацию";
     - "Открыть аннотацию";
     - редактирование узлов мышью.
   - Все новые пользовательские строки должны быть на русском языке.
   - Код должен соответствовать текущему стилю приложения и существующей архитектуре `QAction`, меню, toolbar и SVG-иконок.

Критерии готовности:
   - При открытом изображении команда "Новый контур" доступна в меню "Инструменты".
   - Команда есть на панели инструментов и имеет отдельную SVG-иконку.
   - При запуске команды появляется диалог выбора количества узлов.
   - Значение по умолчанию в диалоге равно `5`.
   - При выборе `5` создаётся окружный контур из пяти узлов в центре изображения.
   - При выборе `3` создаётся треугольный контур.
   - При выборе другого допустимого количества узлов создаётся контур с ровно этим числом узлов.
   - Если пользователь отменил диалог, контур не меняется.
   - Если контур уже был, приложение спрашивает подтверждение перед заменой.
   - После создания контура его можно редактировать существующими инструментами.
   - В проектном режиме новый контур сохраняется в JSON проекта для выбранного изображения.
   - Окно свойств показывает обновлённое количество узлов контура.
   - Гистограммы и свойства контура обновляются после создания нового контура.
   - Все ранее существующие сценарии работы с изображением и контуром продолжают работать.
