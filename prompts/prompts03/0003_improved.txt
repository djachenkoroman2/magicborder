Убери из MagicBorder сценарий одиночной работы с отдельным изображением вне проекта.

Контекст:
MagicBorder теперь является проектным приложением для пакетной обработки группы изображений. Основной сценарий работы строится вокруг проекта, папки `images`, списка изображений проекта, контуров, свойств изображения и JSON-файла проекта. Команды, которые открывают или сохраняют одиночное изображение как самостоятельный файл вне проектного сценария, больше не нужны и только путают интерфейс.

Цель:
аккуратно удалить из приложения пользовательские команды одиночной обработки изображения, сохранив проектный сценарий работы без регрессий.

Удалить из интерфейса:

1. Команду `Открыть изображение`.
2. Команду `Сохранить изображение`.
3. Соответствующие кнопки панели инструментов.
4. Соответствующие пункты меню.
5. Горячие клавиши, подсказки, статусные сообщения и иконки действий, если они больше нигде не используются.

Что оставить:

1. Команды проекта: `Новый проект`, `Открыть проект`, `Сохранить проект`, `Закрыть проект`.
2. Команды управления изображениями внутри проекта: добавление изображений, синхронизация папки `images`, удаление изображения из проекта.
3. Работу с контуром выбранного проектного изображения: создание, автоматическое определение, редактирование, удаление и сохранение контура в JSON проекта.
4. Экспорт списка изображений и экспорт свойств изображения в Excel.
5. Загрузку изображения из записи проекта при выборе элемента списка.

Требования к коду:

1. Удали действия, методы и обработчики, которые нужны только для одиночного открытия или одиночного сохранения изображения.
2. Удали мёртвые импорты, константы, иконки и вспомогательные функции, если после удаления команд они больше не используются.
3. Не ломай проектный режим: открытие проекта должно по-прежнему загружать выбранное изображение на канвас.
4. Не удаляй сохранение проекта и автосохранение аннотации в JSON проекта.
5. Не меняй формат JSON проекта, если для удаления этих команд это не требуется.
6. Если какие-то функции используются и в одиночном, и в проектном сценарии, оставь только ту часть, которая нужна проектному сценарию.

Требования к документации:

1. Обнови README: убери описание открытия одиночного изображения и сохранения изображения вне проекта.
2. Уточни основной пользовательский сценарий: сначала создаётся или открывается проект, затем изображения добавляются в проект или синхронизируются из папки `images`.
3. Убедись, что список возможностей больше не упоминает удалённые команды.

Требования к тестам:

1. Обнови существующие тесты, которые ожидают наличие команд `Открыть изображение` и `Сохранить изображение`.
2. Добавь или обнови проверки, что проектный сценарий по-прежнему работает: открытие проекта, выбор изображения, отображение изображения на канвасе, создание/сохранение контура.
3. Если в тестах проверяется состав меню или панели инструментов, убери из ожидаемого результата удалённые действия.

Проверки после изменений:

1. Запусти синтаксическую проверку изменённых Python-файлов.
2. Запусти релевантные тесты по главному окну, проектам, списку изображений и контурам.
3. В итоговом ответе кратко перечисли удалённые команды, изменённые файлы и выполненные проверки.
